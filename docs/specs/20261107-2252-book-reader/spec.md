# 원서 리더와 공통 메모 저장소

- 작성일: 2026-11-07
- 요약: 넷플릭스 학습 패널의 하이라이트·메모를 확장 프로그램 공통 저장소로 옮기고, 확장 프로그램 안 별도 탭 화면으로 원서 리더와 넷플릭스·원서 메모 모아 보기를 만든다.
- 종류: 변경 건 (기존 크롬 확장 프로그램을 바꾼다)
- 단계: 나누지 않는다. 사용자가 하나의 명세서로 쓰기로 정했다(2026-11-07). `docs/plan.md`는 없다.
- 이 문서는 기획과 요구사항만 담는다. 설계와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 저장소 `mivomad33/netflix-subtitle-study`는 GitHub **공개 저장소**다. 커밋하는 모든 것은 공개된다(4.9).

## 1. 목표

### 지금 상태

- 넷플릭스 영상을 볼 때 학습 패널에서 영어 대사에 하이라이트와 여러 줄 메모를 남길 수 있다(커밋 `7daf7bd`).
- 메모는 넷플릭스 사이트(`https://www.netflix.com`)의 `localStorage`에 `NF_annotations_{videoId}` 키로 저장된다. 이 저장소는 넷플릭스 페이지에서만 읽을 수 있고, 사용자가 브라우저의 사이트 데이터를 지우면 함께 사라진다.
- 사용자는 영어 원서로도 공부한다. 원서 본문은 OCR 등으로 텍스트를 이미 갖고 있다고 본다. 원서를 읽으며 같은 방식으로 하이라이트·메모를 남길 곳이 없다.

### 바꾸려는 이유

- 원서도 PC 크롬 브라우저에서 읽으며 공부한다(사용자, 2026-11-07).
- 영상과 원서에서 배운 표현을 한곳에서 모아 보고, 찾고, 원래 문맥으로 돌아갈 수 있어야 한다. 그러려면 메모가 넷플릭스 사이트가 아니라 확장 프로그램 자체 저장소에 있어야 한다.

### 쓰는 사람

이 확장 프로그램을 쓰는 사용자 본인 한 명. PC 크롬 하나에서 쓴다. 로그인과 여러 사용자는 없다.

### 어느 수준이면 충분한가

- 책 20권, 한 권 본문 최대 200만 자, 메모 전체 5,000개에서 이 문서의 기능이 모두 동작하고 화면이 멈춘 것처럼 보이지 않는다(4.10-3).
- 원서 리더는 한 사람이 매일 읽고 메모하는 데 불편이 없는 수준이면 된다. 출판용 전자책 리더 수준의 조판(쪽 넘김, 하이픈 처리된 양쪽 정렬, 각주)은 필요 없다.

## 2. 확정된 결정과 제약

### 이 명세서에서 정한 것

- **걱정·함정**: 사용자가 따로 짚은 것은 없다(2026-11-07). AI가 찾은 위험(기존 메모 보존, 공개 저장소에 원서 본문을 넣지 않기, 확장 프로그램 ID가 바뀌면 저장소가 비어 보이는 문제)은 요구사항으로 다룬다.
- **디자인**: 기존 학습 패널의 모양(색, 글꼴, 버튼, 하이라이트·메모 모양)에서 디자인 기준을 뽑아 `docs/design.md`로 정리하고, 새 화면은 그 기준으로 만든다(추천안·사용자 승인, 2026-11-07). 이유: 빠르고, 넷플릭스 패널과 원서 리더가 한 제품처럼 보인다. 뺀 안: `design-direction`으로 새 방향 찾기. 읽기 화면에 더 맞을 수 있지만 시간과 비용이 훨씬 든다.
- **공통 저장소**: 확장 프로그램 자체 저장소 `chrome.storage.local`을 쓰고 `unlimitedStorage` 권한을 더한다(추천안·사용자 승인, 2026-11-07).
  - 이유: 넷플릭스 쪽 content script와 확장 프로그램 화면이 모두 직접 읽고 쓸 수 있어 서비스 워커 수명을 신경 쓰지 않아도 되고, 키-값 JSON이라 지금 코드와 모양이 같다. 공식 문서(developer.chrome.com `reference/api/storage`, `develop/concepts/storage-and-cookies`, 2026-11-07 확인)상 기본 한도는 10MB이고 `unlimitedStorage`가 있으면 한도가 풀리며, 브라우저 방문 기록·사이트 데이터 삭제에는 지워지지 않고 확장 프로그램을 제거하면 지워진다.
  - 뺀 안: 확장 프로그램 쪽 IndexedDB. 색인·트랜잭션이 있지만 이 규모(1장)에서는 필요 없고, 넷플릭스 쪽에서는 서비스 워커를 거쳐야 해 일이 늘어난다. 데이터가 수백 MB로 커지면 그때 다시 본다.
  - 독립 검토(서브에이전트 셋, 모델 섞음)에서 둘은 같은 안, 하나는 IndexedDB 안을 냈다. 검토 뒤에도 추천은 바뀌지 않았다.
- **옮길 범위**: 하이라이트·메모만 옮긴다. 모아 보기에 쓰도록 메모마다 영상 제목·시즌·회차를 함께 저장한다. 체크리스트(`NF_checklist_*`), 대시보드 영상 목록(`NF_studied_videos`), 화면·재생 설정은 지금처럼 넷플릭스 `localStorage`에 둔다(추천안·사용자 승인, 2026-11-07).
  - 이유: 바꾸는 범위가 가장 작고 되돌리기 쉽다. 설정은 넷플릭스 화면에서만 쓰고 동기식으로 바로 읽어야 한다.
  - 뺀 안: 체크리스트와 영상 목록까지 옮기기. 사이트 데이터를 지워도 학습 기록이 남는 장점이 있지만, 대시보드·체크리스트 코드를 많이 고쳐야 해 기존 기능이 깨질 위험이 커진다.
- **기존 데이터 처리**: 넷플릭스 `localStorage`의 `NF_annotations_*` 원본은 지우지 않고 공통 저장소로 복사만 한다(추천안·사용자 승인, 2026-11-07). 이유: 옮기다 문제가 생겨도 되돌릴 수 있다. 원본을 언제 지울지는 이 명세서에서 정하지 않는다(넣지 않는 것).
- **백업**: 공통 저장소 전체(책, 메모, 읽기 위치)를 JSON 파일 하나로 내보내고 가져오는 기능을 넣는다(추천안·사용자 승인, 2026-11-07). 이유: 서버가 없고, 확장 프로그램을 제거하면 데이터가 함께 지워진다. 독립 검토 셋과 넓혀 보기 둘이 모두 필요하다고 봤다.
- **장 나누기**: 책 전체를 한 번에 붙여 넣으면 장 제목 줄을 자동으로 찾아 나눠 보여 주고, 저장 전에 나눌 곳을 더하거나 빼고 장 이름을 고칠 수 있게 한다(추천안·사용자 승인, 2026-11-07). 뺀 안: 장마다 따로 붙여 넣기. 단순하지만 OCR로 장을 나눠 뽑지 않았다면 손이 많이 간다.
- **넓혀 보기로 더한 것**(쓰는 사람 관점·비슷한 제품 조사 서브에이전트, 2026-11-07): 사용자가 둘 다 골랐다.
  - 고른 것: 붙여 넣은 본문 정리(줄 끝 줄바꿈 합치기, 줄 끝 하이픈으로 끊긴 단어 잇기, 빈 줄로 문단 나누기), 모아 보기에서 원래 위치로 가기.
  - 보였지만 질문에 넣지 않은 후보: 등록한 뒤 본문 고치기, 사전 찾아보기, 지난 메모 다시 꺼내 보여 주기. "넣지 않는 것"에 적었다.
  - 후보 중 이미 범위에 들어간 것: 백업(위 결정), 이어 읽기와 위치를 잃은 메모 보존(요구사항 4.4-6, 4.1-5).
- **작업 브랜치**: `book-reader` 브랜치에서 구현하고, 사용자가 결과를 확인해 승인하면 main에 머지하고 push한다(추천안·사용자 승인, 2026-11-07). 뺀 안: main에 바로 커밋. 저장 방식이 바뀌는 일이라 확인 전에 main에 섞이지 않게 한다.
- **CI**: GitHub Actions를 새로 둔다. push와 PR에서 타입 검사, 린트, 테스트, 빌드를 돌린다(추천안·사용자 승인, 2026-11-07). 뺀 안: CI 없이 로컬 검증만. 커밋에서 빠진 파일 같은 문제를 늦게 알게 된다.

### 기존에 정해진 것 (다시 묻지 않는다)

- 원서는 PC 크롬에서 읽는다. 태블릿·폰 지원과 별도 웹앱은 하지 않는다(사용자 결정, 2026-11-07. 확장 프로그램은 PC 크롬에서만 돌기 때문에 별도 웹앱 안을 뺐다).
- 원서 기능은 넷플릭스 확장 프로그램과 따로 만들지 않고, 같은 확장 프로그램 안의 별도 탭 화면(`chrome-extension://` 페이지)으로 만든다(추천안·사용자 승인, 2026-11-07). 뺀 안: 별도 확장 프로그램이나 웹앱. 메모를 한곳에 모으기 어렵고 하이라이트·메모 코드를 다시 만들어야 하기 때문이다.
- 원서 본문을 이미지에서 뽑는 일(OCR)은 다루지 않는다. 사용자가 텍스트를 붙여 넣는다(사용자 결정, 2026-11-07).
- 프로젝트 규칙(`.cursor/rules/project-rule.mdc`): React, webpack 빌드. 넷플릭스 페이지에 넣은 코드(`src/pages/Content`)는 `chrome.*`를 쓸 수 없고, 넷플릭스 CSP 때문에 content script(`src/pages/ContentLoader`)·background를 거친다. README나 DEVELOPMENT 문서를 고치면 두 언어 파일(한국어·영어)을 함께 고친다.
- 커밋 메시지는 영어로 쓴다(사용자 전역 지침).

### 제약

- 기존 개발 도구(TypeScript, ESLint, Prettier 설정, Vitest + Testing Library, webpack)를 따른다. 검증 명령은 `npm run typecheck`, `npm run lint`, `npm run test:run`, `npm run build`다.
- 로컬 main은 origin/main보다 커밋 두 개(`7daf7bd`, `14f25f7`)가 앞서 있다. `book-reader` 브랜치는 지금 로컬 main에서 만든다.

## 3. 범위

### 넣는 것

1. 공통 저장소와 넷플릭스 메모 이전(4.1)
2. 넷플릭스 학습 패널이 공통 저장소를 쓰도록 바꾸되 지금 기능 유지(4.2)
3. 원서 등록: 붙여 넣기, 본문 정리, 장 자동 나누기와 고치기, 책 목록·삭제(4.3)
4. 원서 리더: 장 목록, 본문 읽기, 하이라이트·여러 줄 메모, 장 메모 목록, 이어 읽기와 진도(4.4)
5. 모아 보기: 넷플릭스·원서 메모를 함께 보고 검색·거르고, 원래 위치로 가기(4.5)
6. 백업: 내보내기와 가져오기(4.6)
7. 들어가는 길: 툴바 팝업, 넷플릭스 학습 대시보드의 링크(4.7)
8. 디자인 기준 `docs/design.md`와 새 화면(4.8)
9. 데이터 안전과 공개 저장소 보호(4.9)
10. 성능, CI, 개발용 실행, 문서(4.10)

### 넣지 않는 것

- OCR, 이미지·PDF·EPUB 파일에서 본문 뽑기: 사용자가 텍스트를 붙여 넣기로 했다.
- 태블릿·폰, 다른 브라우저 지원: PC 크롬만 쓴다.
- 여러 기기 동기화, 서버, `chrome.storage.sync`: 서버가 없고, sync는 항목당 8KB·전체 100KB 한도라 본문과 메모를 담을 수 없다.
- 체크리스트·대시보드 영상 목록·설정 옮기기: 위 "옮길 범위" 결정.
- 넷플릭스 `localStorage`의 기존 메모 원본 지우기: 되돌릴 수 있게 남긴다. 지울지는 다음에 정한다.
- 등록한 뒤 본문 고치기(OCR 오타 수정), 장 다시 나누기: 이번에는 등록 전 미리 보기에서만 고친다. 고치려면 책을 지우고 다시 등록한다. 넓혀 보기 후보였지만 질문에 넣지 않았다(메모 위치를 지키는 일이 커서).
- 사전 찾아보기, 번역: 넓혀 보기 후보였지만 이번 범위가 아니다.
- 지난 메모를 날마다 다시 보여 주기(복습), 단어장·플래시카드: 다음에 다룰 만하다.
- 원서 메모를 AI 프롬프트에 넣기, 메모 Markdown 내보내기: 백업은 JSON만 한다.
- 원서 하이라이트 색 여러 개, 원서에서 여러 문단에 걸친 하이라이트: 넷플릭스와 같게 한 가지 색, 한 문단 안에서만 고른다.
- 다크 모드: 지금 학습 패널에도 없다.
- 크롬 웹 스토어 등록: 지금처럼 `build` 폴더를 직접 불러와 쓴다.

## 4. 요구사항

### 용어

- **사용자**: 이 확장 프로그램을 쓰는 사람 한 명.
- **공통 저장소**: 확장 프로그램의 `chrome.storage.local`.
- **메모**: 하이라이트 하나와 거기 붙은 메모 글(비어 있을 수 있음). 지금 코드의 `SentenceAnnotation`과 같은 뜻이다.
- **출처**: 메모가 붙은 곳. 넷플릭스 영상의 한 대사, 또는 원서의 한 문단.
- **원서 리더**: 확장 프로그램 안 탭 화면에서 책을 읽는 화면. **모아 보기**: 출처와 상관없이 메모를 모아 보는 화면. 둘이 한 페이지 안의 다른 화면이어도 되고 다른 페이지여도 된다(AI 재량).
- **넷플릭스 쪽**: 넷플릭스 페이지에 넣은 코드(`src/pages/Content`, `src/pages/ContentLoader`).

### 4.1 공통 저장소와 이전

- **4.1-1** 메모는 공통 저장소에 저장한다. 넷플릭스 메모와 원서 메모는 같은 모양으로 저장하고, 출처 종류(넷플릭스/원서), 출처 ID(영상 ID/책 ID), 출처 안 위치, 출처 원문, 고른 글, 메모 글, 만든 시각, 고친 시각을 갖는다. 넷플릭스 메모는 영상 제목, 시즌·회차 번호와 회차 제목(있으면)도 갖는다.
  - 확인: 단위 테스트로 넷플릭스 메모와 원서 메모를 저장하고 다시 읽어 위 항목이 모두 남는지 본다. 통합 테스트로 넷플릭스 쪽에서 만든 메모가 공통 저장소(가짜 `chrome.storage.local`)에 영상 제목과 함께 들어가는지 본다.
- **4.1-2** `src/manifest.json`에 `storage`, `unlimitedStorage` 권한을 더한다. 다른 권한이나 호스트 권한은 더하지 않는다.
  - 확인: 단위 테스트(또는 검사 스크립트)로 빌드된 `build/manifest.json`의 `permissions`가 정확히 이 둘인지, `host_permissions`가 없는지 본다.
- **4.1-3** 넷플릭스 페이지를 처음 열 때 넷플릭스 `localStorage`의 `NF_annotations_*`를 모두 공통 저장소로 복사한다. 복사가 끝나면 끝났다는 표시를 공통 저장소에 남기고, 그 뒤로는 넷플릭스 쪽도 공통 저장소만 읽고 쓴다. 원본 키는 지우지도 바꾸지도 않는다.
  - 복사 중 실패하면(저장 오류, 형식이 깨진 키) 끝났다는 표시를 남기지 않고 다음에 다시 시도한다. 형식이 깨진 키 하나가 나머지 복사를 막지 않는다.
  - 같은 메모가 이미 공통 저장소에 있으면(같은 메모 ID) 다시 넣지 않는다. 여러 번 돌아도 메모가 겹치지 않는다.
  - 옛 메모에는 영상 제목이 없다. 복사할 때 넷플릭스 `NF_studied_videos`에 그 영상이 있으면 제목·회차를 채우고, 없으면 비워 두고 모아 보기에서 "제목 없는 영상 (ID)"처럼 보인다.
  - 확인: 통합 테스트로 (a) 영상 둘의 메모 셋이 든 `localStorage`에서 복사 뒤 공통 저장소에 메모 셋이 제목과 함께 있고 원본 키 값이 바이트 단위로 그대로인지, (b) 두 번 돌려도 셋인지, (c) 깨진 JSON 키 하나와 정상 키 하나가 있으면 정상 키는 복사되고 끝났다는 표시는 남지 않는지, (d) 저장 오류를 흉내 내면 표시가 남지 않고 다음 실행에서 복사되는지 본다.
- **4.1-4** 넷플릭스 페이지 코드와 content script 사이의 메시지는 이 확장 프로그램이 보낸 형식의 메시지만 처리한다. 넷플릭스 페이지의 다른 스크립트가 같은 이름의 메시지를 보내도 메모 외의 공통 저장소 키를 읽거나 지울 수 없고, 형식이 틀린 메시지는 무시한다.
  - 확인: 단위 테스트로 content script의 메시지 처리기에 (a) 정상 메모 저장 요청은 처리되고, (b) 메모가 아닌 키(책 본문 등)를 읽거나 지우는 요청, 형식이 틀린 요청은 공통 저장소를 바꾸지 않고 무시되는지 본다.
- **4.1-5** 위치를 다시 찾지 못한 메모(출처 원문이 바뀌었거나 맞는 대사·문단이 없는 메모)는 지우지 않는다. 화면의 본문에는 보이지 않지만 모아 보기에는 나오고, 지울 수 있다.
  - 확인: 통합 테스트로 원문이 다른 메모가 학습 패널·원서 본문에는 하이라이트로 그려지지 않고, 모아 보기 목록에는 "위치를 찾지 못함" 표시와 함께 나오며, 저장소에서 사라지지 않는지 본다.
- **4.1-6** 넷플릭스 탭과 원서 리더 탭을 함께 열어 두어도 메모가 사라지지 않는다. 같은 메모를 두 탭에서 고치면 나중에 저장한 것이 이긴다. 한 탭에서 만든 메모는 다른 탭의 모아 보기에 다시 열거나 새로 고치면 보인다.
  - 확인: 통합 테스트로 두 저장 경로(넷플릭스 쪽, 리더 쪽)에서 서로 다른 메모를 번갈아 저장해도 둘 다 남는지(한쪽이 다른 쪽을 통째로 덮어쓰지 않는지) 본다.
- **4.1-7** 확장 프로그램 ID를 `manifest.json`의 `key`로 고정한다. 그래서 `build` 폴더 위치가 바뀌어도 같은 공통 저장소를 본다. 비밀 키 파일(`.pem`)은 커밋하지 않는다.
  - 확인: 검사 스크립트로 `build/manifest.json`에 `key`가 있는지, 저장소 안에 `.pem` 파일이 커밋되지 않았는지(`git ls-files '*.pem'`가 비었는지) 본다. 고정된 ID는 결과 보고서에 적는다.

### 4.2 넷플릭스 학습 패널 (기존 기능 유지)

- **4.2-1** 넷플릭스 학습 패널의 하이라이트·메모 기능은 지금과 똑같이 동작한다. 글 고르기와 도구막대, 하이라이트, 메모 영역(여러 줄, 자동 저장, Esc로 닫기), 겹치는 선택이면 기존 하이라이트 열기, 메모가 있는 하이라이트 지울 때 확인, 메모를 여는 동안 영상 멈춤과 자동 스크롤 멈춤, 영어 숨김 모드 처리, 키 입력이 넷플릭스로 넘어가지 않음.
  - 공통 저장소가 비동기라서 패널을 연 직후 메모를 불러오는 동안에는 하이라이트가 잠시 없을 수 있지만, 불러온 뒤에는 그려지고 그 사이 만든 메모가 사라지지 않는다.
  - 확인: 기존 `SentenceList.test.tsx`, `StudyPanel.test.tsx`의 하이라이트·메모 테스트가 공통 저장소(가짜)로 바꾼 뒤에도 같은 기대값으로 통과한다. 불러오기 전에 만든 메모가 불러온 뒤에도 남는지 통합 테스트를 더한다.
- **4.2-2** 메모와 상관없는 기존 기능(자막 정렬, 실시간 추적, 단축키 Q·R·T·W·E·A·S·D·Space, 자동 멈춤·반복·건너뛰기, 영상 위 자막, 체크리스트·회차, AI 프롬프트 복사, 대시보드, 패널 폭·글자 크기·페이지당 대사 수)은 바뀌지 않는다.
  - 확인: 기존 테스트 전체가 기대값을 바꾸지 않고 통과한다. 메모와 무관한 기존 테스트의 기대값을 바꿨다면 그 이유를 진행 기록에 적는다.
- **4.2-3** 학습 기록 초기화, 페이지당 대사 수 변경, 대시보드에서 영상 삭제는 지금처럼 메모를 지우지 않는다.
  - 확인: 통합 테스트로 세 동작 뒤에 공통 저장소의 그 영상 메모가 남는지 본다.

### 4.3 원서 등록

- **4.3-1** 원서 리더에서 새 책을 등록할 수 있다. 책 제목(필수), 지은이(선택), 본문(필수, 붙여 넣기)을 넣는다. 제목이나 본문이 비면 저장할 수 없고 무엇이 비었는지 보인다.
  - 확인: 통합 테스트로 제목 없이, 본문 없이 저장하면 막히고 안내가 보이는지, 둘 다 넣으면 책 목록에 나오는지 본다.
- **4.3-2** 붙여 넣은 본문을 정리하는 기능이 있다. 기본으로 켜져 있고 끌 수 있으며, 결과는 저장 전에 미리 보기로 보인다.
  - 문단 안에서 줄 끝 줄바꿈은 공백 하나로 합친다. 빈 줄(공백만 있는 줄 포함)은 문단 경계로 남는다.
  - 줄 끝 하이픈으로 끊긴 단어는 잇는다(`exam-\nple` → `example`). 줄 중간의 하이픈(`well-known`)과 줄 끝이어도 다음 줄이 대문자나 숫자로 시작하는 경우는 그대로 둔다.
  - 연달아 있는 공백은 하나로 줄인다. 문단 앞뒤 공백은 지운다.
  - 확인: 단위 테스트로 위 각 규칙과, 닮았지만 바뀌면 안 되는 입력(`well-known`, 줄 끝 `-` 다음 줄이 `The`로 시작, 대시 `—`, 빈 줄 둘 이상)이 그대로인지 본다. 정리를 끄면 줄바꿈이 그대로 문단을 나누는지 본다.
- **4.3-3** 본문에서 장 제목 줄을 자동으로 찾아 장으로 나눠 미리 보기로 보인다. 찾는 대상은 혼자 한 줄인 `Chapter 1`, `CHAPTER ONE`, `Chapter I`, `Part 2`, 숫자·로마 숫자만 있는 줄(`1`, `IV`) 같은 형태이고, 정확한 규칙은 AI 재량이다. 장 제목을 하나도 못 찾으면 책 전체를 장 하나로 둔다.
  - 확인: 단위 테스트로 위 형태가 각각 장으로 나뉘는지, 문장 안의 "chapter"(`In this chapter we...`)와 문단 안의 숫자는 나누지 않는지, 장 제목이 없으면 장 하나인지 본다.
- **4.3-4** 저장 전 미리 보기에서 나눌 곳을 더하거나 빼고 장 이름을 고칠 수 있다. 장 제목 줄 앞에 본문이 있으면(머리말 등) 그 부분도 장 하나로 남고 이름을 붙일 수 있다. 저장하면 미리 보기와 똑같이 나뉜 책이 만들어진다.
  - 확인: 통합 테스트로 미리 보기에서 나눈 곳 하나를 빼고, 한 곳을 더하고, 장 이름을 바꾼 뒤 저장하면 저장된 책의 장 개수·이름·첫 문단이 그대로인지 본다.
- **4.3-5** 본문 200만 자를 붙여 넣어도 미리 보기와 저장이 끝나고, 그동안 대기 표시가 보인다(4.10-3).
  - 확인: 4.10-3의 성능 테스트.
- **4.3-6** 책 목록에서 책을 지울 수 있다. 지울 때 "책과 메모 N개가 지워진다"는 확인을 받고, 확인하면 그 책의 본문, 메모, 읽기 위치가 모두 지워진다. 다른 책과 넷플릭스 메모는 남는다.
  - 확인: 통합 테스트로 책 둘(각각 메모 있음)과 넷플릭스 메모가 있을 때 한 책을 지우면 그 책의 데이터만 사라지고 나머지가 남는지, 확인에서 취소하면 아무것도 지워지지 않는지 본다.

### 4.4 원서 리더

- **4.4-1** 책을 열면 장 목록과 한 장의 본문이 보인다. 장 목록에서 장을 누르면 그 장 본문으로 바뀐다. 본문은 문단 단위로 보인다.
  - 확인: 통합 테스트로 장 셋인 책을 열고 두 번째 장을 누르면 그 장의 첫 문단이 보이고 첫 장 문단은 보이지 않는지 본다.
- **4.4-2** 본문에서 한 문단 안의 글을 고르면 넷플릭스 학습 패널과 같은 하이라이트·메모 동작을 한다: 도구막대(하이라이트/메모), 앞뒤 공백 빼기, 겹치는 선택이면 기존 하이라이트 열기, 칠한 곳 누르면 메모 영역 열기, 메모가 있으면 밑줄과 표시, 메모 영역(기본 6줄 이상, 글이 늘면 자동으로 늘어남, 손으로 크기 조절, 고른 글 인용, 자동 저장, Esc로 닫기), 메모가 있는 하이라이트를 지울 때 확인. 두 문단에 걸친 선택에는 도구막대가 뜨지 않는다.
  - 확인: 통합 테스트로 넷플릭스 쪽 `SentenceList.test.tsx`의 하이라이트·메모 시나리오와 같은 시나리오를 원서 문단에 대해 돌리고, 두 문단에 걸친 선택에는 도구막대가 없는지 본다.
- **4.4-3** 원서 메모는 문단 원문과 문단 안 위치, 고른 글을 함께 저장해, 원문이 같은 문단에만 다시 그려진다(4.1-5).
  - 확인: 단위 테스트로 위치는 맞지만 고른 글이 다른 메모, 다른 문단의 메모가 그려지지 않는지 본다.
- **4.4-4** 본문 옆에 지금 장의 메모 목록이 보인다. 항목마다 고른 글과 메모 앞부분이 보이고, 누르면 본문의 그 하이라이트로 스크롤되고 그 메모 영역이 열린다. 메모가 없는 장은 비어 있다는 안내가 보인다.
  - 확인: 통합 테스트로 메모 둘인 장에서 목록 두 번째 항목을 누르면 그 하이라이트의 메모 영역이 열리는지(스크롤은 `scrollIntoView` 호출로 확인), 메모 없는 장에서 빈 안내가 보이는지 본다.
- **4.4-5** 메모 영역 안의 키 입력은 원서 리더의 다른 단축키(있다면)에 넘어가지 않는다.
  - 확인: 통합 테스트로 메모 영역에서 누른 키가 `window`의 keydown 처리기에 닿지 않는지 본다.
- **4.4-6** 책마다 마지막으로 읽던 장과 위치(문단)를 기억해, 다시 열면 그 장의 그 문단 근처가 보인다. 책 목록에는 책마다 진도(읽은 장 위치 / 전체 장 수)가 보인다.
  - 확인: 통합 테스트로 장 셋인 책에서 두 번째 장의 다섯 번째 문단을 보다가 화면을 닫고 다시 열면 두 번째 장이 열리고 그 문단으로 스크롤하는지(`scrollIntoView` 대상으로 확인), 책 목록에 "2/3장"처럼 보이는지 본다. 진도 표기 문구는 AI 재량이다.
- **4.4-7** 원서 리더의 본문 글자 크기를 조절할 수 있고, 다시 열어도 유지된다.
  - 확인: 통합 테스트로 글자 크기를 바꾸고 다시 렌더링하면 같은 크기인지 본다.

### 4.5 모아 보기

- **4.5-1** 넷플릭스 메모와 원서 메모가 한 목록에 나온다. 기본 순서는 고친 시각이 최근인 것부터다. 항목마다 고른 글, 메모 글, 출처(영상 제목과 회차 / 책 제목과 장 이름), 출처 원문(대사 / 문단, 길면 고른 글 주변만), 고친 날짜가 보인다.
  - 확인: 통합 테스트로 넷플릭스 메모 둘과 원서 메모 하나를 넣고 고친 시각 순서와 각 항목의 출처 표시가 맞는지 본다.
- **4.5-2** 검색어를 넣으면 고른 글, 메모 글, 출처 원문, 출처 제목 중 하나에 검색어가 있는 메모만 나온다. 대소문자를 가리지 않는다. 결과가 없으면 없다는 안내가 보인다.
  - 확인: 단위 테스트로 각 필드에만 검색어가 있는 메모가 모두 걸리는지, 대문자 검색어로 소문자 글이 걸리는지, 어디에도 없는 메모는 빠지는지, 결과가 없으면 안내가 보이는지 본다.
- **4.5-3** 출처로 거를 수 있다: 전체 / 넷플릭스만 / 원서만, 그리고 특정 책이나 특정 영상 하나. 메모 글이 있는 것만 보는 선택도 있다. 거르기와 검색은 함께 쓸 수 있다.
  - 확인: 단위 테스트로 각 거르기와 검색어를 함께 쓴 결과가 맞는지 본다.
- **4.5-4** 모아 보기에서 메모 글을 고치거나 메모를 지울 수 있고, 원서 리더·학습 패널과 같은 규칙(자동 저장, 메모가 있으면 지울 때 확인)을 따른다.
  - 확인: 통합 테스트로 모아 보기에서 고친 메모 글이 저장소에 저장되는지, 지운 메모가 저장소와 목록에서 사라지는지 본다.
- **4.5-5** 원서 메모를 누르면(또는 "원래 위치로" 버튼을 누르면) 원서 리더가 그 책의 그 장을 열고 그 하이라이트로 스크롤해 메모 영역을 연다.
  - 확인: 통합 테스트로 원서 메모에서 원래 위치로 가면 리더가 해당 장을 열고 해당 하이라이트의 메모 영역이 열리는지 본다.
- **4.5-6** 넷플릭스 메모의 "원래 위치로"를 누르면 새 탭에 넷플릭스의 그 영상이 열리고, 그 대사 시작 시각부터 재생된다. 넷플릭스에 로그인하지 않았거나 영상을 볼 수 없으면 넷플릭스가 보여 주는 화면이 그대로 보인다(따로 처리하지 않는다).
  - 확인: 단위 테스트로 넷플릭스 메모에서 만드는 주소(영상 ID와 시작 시각 포함)가 맞는지 본다. 그 시각부터 실제로 재생되는지는 넷플릭스 로그인이 필요해 사용자가 마지막에 확인한다.
- **4.5-7** 위치를 찾지 못한 메모(4.1-5)는 목록에 "위치를 찾지 못함" 표시가 붙고, 원래 위치로 가기 대신 출처만 연다(원서는 그 장, 넷플릭스는 그 영상 처음).
  - 확인: 통합 테스트로 표시가 보이는지, 원서 메모는 그 장이 열리는지 본다.

### 4.6 백업

- **4.6-1** 공통 저장소의 모든 데이터(책 본문, 메모, 읽기 위치, 원서 리더 설정)를 JSON 파일 하나로 내보낼 수 있다. 파일 이름에 날짜가 들어가고(`nf-study-backup-YYYYMMDD.json` 형태, 정확한 이름은 AI 재량), 파일에 형식 버전이 들어간다.
  - 파일 이름의 날짜와 화면에 보이는 날짜는 사용자 PC의 현지 시각 기준이다.
  - 확인: 단위 테스트로 내보낸 내용에 책·메모·읽기 위치와 형식 버전이 모두 있는지, 파일 이름이 날짜 형식인지 본다.
- **4.6-2** 내보낸 파일을 가져오면 지금 데이터와 합친다. 같은 ID의 책·메모는 고친 시각이 더 최근인 쪽이 남고, 없던 것은 더해진다. 지금 데이터에만 있는 것은 지워지지 않는다. 가져오기 전에 "책 N권, 메모 M개를 합친다"는 확인을 받는다.
  - 확인: 단위 테스트로 (a) 겹치는 메모 하나(파일 쪽이 최근), 파일에만 있는 메모 하나, 지금에만 있는 메모 하나로 가져오면 셋 다 있고 겹친 것은 파일 쪽 내용인지, (b) 겹치는 메모의 지금 쪽이 최근이면 지금 쪽이 남는지 본다.
- **4.6-3** 형식이 틀린 파일(JSON이 아님, 형식 버전 없음, 모르는 상위 버전, 필드가 빠진 메모)을 가져오면 무엇이 문제인지 안내하고 데이터를 하나도 바꾸지 않는다.
  - 확인: 단위 테스트로 각 경우 저장소가 가져오기 전과 같고 오류 안내가 나오는지 본다. 정상 파일은 통과하는지 함께 본다.
- **4.6-4** 내보내기·가져오기는 원서 리더나 모아 보기에서 찾을 수 있는 곳(설정, 메뉴 등)에 있다. 위치는 AI 재량이다.
  - 확인: `design-check` 과제 수행에 "백업 파일을 내보낸다"를 넣는다.

### 4.7 들어가는 길

- **4.7-1** 툴바의 확장 프로그램 아이콘을 누르면 뜨는 팝업에 "원서 리더"와 "메모 모아 보기" 버튼이 있고, 누르면 새 탭에 그 화면이 열린다. 지금의 기본 틀 팝업(React 로고, "Learn React!")은 없앤다.
  - 확인: 통합 테스트로 팝업 버튼을 누르면 `chrome.tabs.create`가 해당 확장 프로그램 페이지 주소로 불리는지 본다.
- **4.7-2** 넷플릭스 학습 대시보드(넷플릭스 상단 메뉴의 탭)에 "메모 모아 보기"와 "원서 리더"로 가는 링크가 있고, 누르면 새 탭에 열린다.
  - 확인: 통합 테스트로 대시보드의 링크를 누르면 content script로 열기 요청이 가는지 본다. 실제 넷플릭스 화면에서 열리는지는 사용자가 마지막에 확인한다.
- **4.7-3** 확장 프로그램 기본 틀로만 남아 있고 쓰지 않는 화면(새 탭 덮어쓰기 `newtab`, `options`, `devtools`, `panel`)은 이번 화면에 쓰지 않으면 동작을 바꾸지 않는다. 새 탭 페이지를 덮어쓰는 설정(`chrome_url_overrides`)은 더하지 않는다.
  - 확인: 검사 스크립트로 `build/manifest.json`에 `chrome_url_overrides`가 없는지 본다.

### 4.8 디자인과 화면

- **4.8-1** 화면은 `docs/design.md`를 따른다. 이 기준은 기존 학습 패널의 모양에서 뽑아 준비 단계에서 만들었다(6장). 새 화면(원서 리더, 책 등록, 모아 보기, 팝업)은 그 기준의 색·글꼴·간격·컴포넌트로 만들고, 기준에 없는 컴포넌트(장 목록, 검색칸, 거르기 등)는 기준의 값으로 만든다. 학습 패널 자체의 모양은 바꾸지 않는다. 기준을 고쳐야 하면 고친 곳과 이유를 진행 기록에 적는다.
  - 확인: `design-check` 깨끗한 회차(기준 대조 포함).
- **4.8-2** 화면은 PC 크롬 기준이다. 확인할 폭은 1280px, 1440px, 그리고 창을 좁힌 1024px이다. 1024px에서도 가로 스크롤이 생기지 않고, 장 목록·메모 목록은 접히거나 아래로 내려가도 된다. 모바일 폭은 지원하지 않는다.
  - 확인: `design-check`가 세 폭에서 원서 리더(책 없음, 책 목록, 읽기, 메모 영역 열림, 메모 많은 장), 책 등록(빈 상태, 정리 미리 보기, 입력 오류, 저장 중 대기), 모아 보기(메모 없음, 메모 많음, 검색 결과 없음, 위치를 찾지 못한 메모), 가져오기 오류, 팝업을 찍어 확인한다.
- **4.8-3** 키보드로 주요 흐름(책 열기, 장 바꾸기, 검색, 메모 영역 닫기)을 할 수 있다. 문구는 지금 학습 패널처럼 한국어 존댓말(~합니다/~하세요)로 쓴다.
  - 확인: `design-check` 키보드 점검과 깨끗한 회차.
- **4.8-4** 빈 상태와 오류: 책이 없으면 "책 등록" 안내, 메모가 없으면 만드는 방법 안내, 저장 실패(저장소 오류)면 "저장하지 못했습니다" 안내가 보이고 입력한 글은 화면에 남는다.
  - 확인: 통합 테스트로 저장소 쓰기 실패를 흉내 내면 안내가 보이고 메모 영역의 글이 지워지지 않는지 본다. 빈 상태는 `design-check`.

### 4.9 데이터 안전과 공개 저장소

- **4.9-1** 테스트·시안·스크린샷에 쓰는 책 본문은 저작권이 끝난(퍼블릭 도메인) 글이나 직접 쓴 글만 쓴다. 사용자가 등록한 실제 원서 본문, 사용자의 실제 메모, 넷플릭스 실제 자막·대사는 저장소, 빌드 결과물, 스크린샷에 넣지 않는다.
  - 확인: 커밋 전에 테스트·시안에 쓴 본문의 출처를 진행 기록에 적고, 스크린샷은 테스트 데이터로만 찍는다. `git ls-files`에 백업 JSON(`nf-study-backup-*.json`)이나 `.pem`이 없는지 검사 스크립트로 본다.
- **4.9-2** 공통 저장소의 데이터를 외부로 보내지 않는다. 원서 리더·모아 보기는 외부 스크립트, 외부 글꼴, 분석 도구를 불러오지 않는다(넷플릭스 링크를 새 탭으로 여는 것만 예외).
  - 확인: 빌드된 원서 리더·모아 보기·팝업 HTML과 번들에 `http://`·`https://`로 시작하는 스크립트·스타일 로드나 `fetch`/`XMLHttpRequest` 호출이 없는지 검사 스크립트로 본다(넷플릭스 주소 문자열은 허용). 검사 스크립트가 일부러 넣은 외부 `<script src="https://...">`를 잡는지도 함께 확인한다.

### 4.10 성능, CI, 개발용 실행, 문서

- **4.10-1** GitHub Actions 워크플로를 둔다. push(모든 브랜치)와 PR에서 `npm ci` 뒤 `npm run typecheck`, `npm run lint`, `npm run test:run`, `npm run build`를 돌린다. Node 버전은 고정하고(`.nvmrc` 등, 버전은 AI 재량) 로컬과 같은 명령을 쓴다.
  - 확인: `book-reader` 브랜치를 push한 뒤 마지막 커밋의 워크플로가 성공하는지 `gh run` 으로 본다.
- **4.10-2** AI가 원서 리더·모아 보기·팝업 화면을 브라우저에서 확인할 수 있게, 확장 프로그램으로 불러오지 않고도 이 화면들을 개발 서버에서 띄우는 방법을 둔다. 이때 `chrome.storage.local`·`chrome.tabs`는 개발용 대체로 바꾸고, 테스트 데이터를 채우는 방법도 둔다. 이 대체는 `npm run build` 결과물에 들어가지 않는다.
  - 확인: 개발 서버로 화면을 띄워 `design-check`를 돌린다. 검사 스크립트로 `build/` 번들에 개발용 대체 저장소 표시 문자열(AI가 정함)이 없는지 본다.
- **4.10-3** 성능: 책 20권(그중 한 권 200만 자), 메모 5,000개일 때 (a) 200만 자 붙여 넣기에서 정리·장 나누기 미리 보기가 3초 안에 나오고 그동안 대기 표시가 보이며, (b) 장 하나(최대 20만 자)를 여는 데 1초 안, (c) 모아 보기 검색 결과가 0.5초 안에 나온다. 측정은 개발 서버와 Playwright로 한다.
  - 확인: 위 데이터를 만드는 스크립트와 Playwright 측정 스크립트로 세 시간을 재서 결과 보고서에 적는다. jsdom 단위 테스트로는 시간을 재지 않는다(실제 브라우저 성능과 달라서).
- **4.10-4** 문서를 고친다. README·README.en(기능 소개에 원서 리더·모아 보기·백업, 들어가는 길), DEVELOPMENT·DEVELOPMENT.en(저장 위치: 공통 저장소와 넷플릭스 `localStorage`의 나뉨, 이전 방식, 개발 서버로 화면 띄우기, CI, 주요 파일, 디자인 기준 `docs/design.md` 링크). 두 언어 파일 내용이 같다.
  - 확인: 고친 문서에 위 항목이 있는지, 두 언어 파일의 절 구성이 같은지 본다.

## 5. 완료 정의

### AI가 확인하고 끝낸다

- 4장의 모든 요구사항이 확인을 통과했다("사용자가 마지막에 확인한다"로 둔 부분은 그 전까지 AI가 할 일을 끝냈다).
- `npm run typecheck`, `npm run lint`, `npm run test:run`, `npm run build`가 로컬에서 통과하고, `book-reader` 브랜치 마지막 커밋의 CI가 성공했다.
- 새 화면이 `design-check` 깨끗한 회차를 통과했고 시각 회귀 테스트로 남았다.
- 결과 보고서에 적을 것(이 문서만의 항목): 고정된 확장 프로그램 ID, 이전 동작 방식(언제 복사되고 원본은 어떻게 남는지), 개발 서버로 화면 띄우는 명령, 4.10-3 측정값, 확장 프로그램을 다시 불러오는 방법.

### 사용자가 마지막에 확인한다

1. `book-reader` 브랜치의 `build` 폴더를 크롬에 다시 불러온다. 확장 프로그램 ID가 바뀌므로(4.1-7) 기존 것을 제거하고 새로 불러와야 할 수 있다. 보고서의 안내를 따른다.
2. 넷플릭스에서 하이라이트·메모가 있던 영상을 열고, 기존 메모가 그대로 보이는지, 새 메모를 만들고 고치고 지울 수 있는지 본다.
3. 원서 리더에서 실제 원서 본문(OCR 결과)을 붙여 넣어 정리·장 나누기 결과가 쓸 만한지, 읽으며 메모가 잘 되는지 본다.
4. 모아 보기에서 넷플릭스 메모의 "원래 위치로"를 눌러 넷플릭스가 그 대사 시각부터 재생되는지 본다(4.5-6).
5. 넷플릭스 학습 대시보드의 링크로 원서 리더·모아 보기가 열리는지 본다(4.7-2).
6. 내보내기 파일을 한 번 받아 둔다.

## 7. 진행 규칙

- 작업 브랜치: 지금 로컬 main에서 `book-reader`를 만들어 거기에 작업 단위로 커밋한다. main에 직접 커밋하지 않는다.
- 머지: 사용자가 `review-done`에서 통과와 머지를 승인하면 `book-reader`를 main에 머지하고(fast-forward가 되면 fast-forward, 아니면 머지 커밋) origin/main에 push한다. 머지 뒤 main의 CI가 성공하는지 본다.

### 사전 승인

- `book-reader` 브랜치를 origin에 push한다(CI를 돌리기 위해). 횟수 제한 없음.
- GitHub Actions 워크플로 파일을 더하고, 그 실행 결과를 `gh run`으로 읽는다.
- `src/manifest.json`에 `storage`, `unlimitedStorage` 권한과 `key`를 더한다. `key`를 만들 때 생기는 비밀 키 파일은 저장소 밖(스크래치 폴더)에 두고 커밋하지 않는다.
- 개발용 npm 패키지 설치(테스트·개발 서버·측정용 devDependencies). 런타임 의존성(`dependencies`)은 꼭 필요할 때만 더하고 이유를 진행 기록에 적는다.
- 비용이 드는 일: 없음. 비용이 생기는 행동은 하지 않는다.

### 멈추고 물을 것

- 넷플릭스 `localStorage`의 원본 메모를 지우거나 바꿔야만 요구사항을 만족할 수 있다고 판단될 때.
- `storage`, `unlimitedStorage` 말고 다른 권한(호스트 권한, `tabs` 권한 등)이 꼭 필요할 때. (`chrome.tabs.create`로 확장 프로그램 페이지나 넷플릭스 주소를 여는 데는 `tabs` 권한이 필요 없다.)
- main에 직접 push하거나 force push가 필요할 때.
- 요구사항끼리 부딪쳐 둘 다 만족할 수 없을 때.
