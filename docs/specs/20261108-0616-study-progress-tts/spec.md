# 원서 학습 진행률과 소리 내어 읽기

- 작성일: 2026-11-08
- 요약: 원서 리더에 장마다 "학습 완료" 체크와 책 한 권의 학습 진행률을 더하고, 브라우저 내장 음성으로 본문을 소리 내어 읽어 주는 기능(TTS)을 더한다.
- 종류: 변경 건(이미 있는 원서 리더를 바꾼다)
- 단계: 나누지 않는다. `docs/plan.md`는 없다.
- 검토: 사용자가 `review-spec` 검토 없이 바로 구현하기로 정했다(추천안·사용자 승인, 2026-11-08).
- 이 문서는 기획과 요구사항만 담는다. 설계와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 저장소 `mivomad33/netflix-subtitle-study`는 GitHub **공개 저장소**다. 커밋하는 모든 것은 공개된다.

## 1. 목표

### 지금 상태

- 원서 리더(`reader.html`, 명세서 `docs/specs/20261107-2252-book-reader`)가 있다. 책을 붙여 넣어 장으로 나눠 등록하고, 장별로 읽으며 하이라이트·메모를 남긴다.
- 책 목록의 "N/M장"은 마지막으로 읽던 장을 보여 줄 뿐이다(`BookList.tsx`의 `progressLabel`). 그 장을 공부했는지는 알 수 없다.
- 본문을 소리로 들을 방법이 없다.

### 바꾸려는 이유

- 장마다 공부를 끝냈는지 표시하고, 책 한 권을 얼마나 공부했는지 한눈에 보고 싶다(사용자, 2026-11-08).
- 원서를 읽으며 발음과 리듬을 듣고 싶다. 무료로 할 수 있으면 무료로 한다(사용자, 2026-11-08).

### 쓰는 사람

이 확장 프로그램을 쓰는 사용자 본인 한 명. PC 크롬(macOS)에서 쓴다.

### 어느 수준이면 충분한가

- 진행률은 책 목록과 리더에서 한눈에 보이면 된다. 통계·그래프·날짜별 기록은 필요 없다.
- 소리 내어 읽기는 크롬이 주는 음성 품질이면 된다. 사람 성우 수준의 음성(유료 API)은 이번에 필요 없다.
- 앞 명세서의 규모(책 20권, 한 권 200만 자, 장 하나 최대 20만 자, 메모 5,000개)에서 이 문서의 기능도 멈춘 것처럼 보이지 않는다.

## 2. 확정된 결정과 제약

### 이 명세서에서 정한 것

- **학습 완료는 장마다 체크 하나**로 한다(추천안·사용자 승인, 2026-11-08). 이유: 화면과 데이터가 단순하고, 단계는 나중에 늘릴 수 있다. 뺀 안: 넷플릭스 학습 패널처럼 단계별 체크리스트(읽기 → 메모 정리 → 소리 내어 읽기 등). 처음부터 단계를 두면 화면과 데이터가 복잡해진다.
- **진행률은 글자 수 기준**으로 계산하고 장 수도 함께 보인다(추천안·사용자 승인, 2026-11-08). 이유: 원서는 장 길이 차이가 커서, 장 수로만 세면 짧은 머리말 하나가 큰 비율을 차지한다. 뺀 안: 장 수 기준.
- **읽던 위치 표시와 완료를 나눈다.** 지금의 "N/M장"(마지막으로 읽던 장)은 이어 읽기 표시로 바꿔, 학습 완료와 헷갈리지 않게 한다(추천안·사용자 승인, 2026-11-08).
- **소리 내어 읽기는 브라우저 내장 Web Speech API(`speechSynthesis`)**로 한다(추천안·사용자 승인, 2026-11-08). 이유: 무료이고 새 권한이 필요 없다. 뺀 안: 유료 음성 API(Google Cloud, Azure, OpenAI, ElevenLabs 등). 품질은 더 좋지만 API 키 관리, 외부 전송, 사용량 비용이 따른다. 내장 음성으로 써 본 뒤 아쉬우면 다음 명세서에서 다룬다.
- **온라인 음성은 설정으로 켠다**(사용자 결정, 2026-11-08).
  - 기기 음성: 컴퓨터(macOS)에 설치된 음성. 글이 밖으로 나가지 않는다.
  - 온라인 음성: 크롬이 주는 "Google …" 음성처럼, 읽을 글을 외부 서버로 보내 소리를 받아 오는 음성. 무료지만 글이 외부로 나간다.
  - 기본은 기기 음성만 음성 목록에 보인다. 사용자가 설정에서 "온라인 음성도 쓰기"를 켜면 온라인 음성도 목록에 나온다. 설정 옆에 "글이 외부(Google 등)로 전송됩니다"를 적는다.
  - 처음에는 두 종류를 모두 목록에 보이고 표시만 붙이는 안을 골랐다가(사용자, 2026-11-08), 글이 외부로 나간다는 점을 듣고 설정으로 빼기로 바꿨다(사용자, 2026-11-08).
  - 이것은 앞 명세서 4.9-2("공통 저장소의 데이터를 외부로 보내지 않는다")의 예외다. 사용자가 설정을 켜고 온라인 음성을 고른 경우에만, 그 음성으로 읽는 글이 외부로 간다.
- **걱정·함정**: 사용자가 따로 짚은 것은 없다(2026-11-08). AI가 찾은 위험(온라인 음성의 외부 전송, 크롬 내장 음성의 알려진 동작 문제, 이미 저장한 책의 글자 수)은 요구사항으로 다룬다.
- **장 끝에서 읽기**: 소리 내어 읽기는 장 끝에서 멈추고, "다음 장"으로 넘어갈 수 있게 한다(추천안·사용자 승인, 2026-11-08). 이유: 장 단위로 공부하는 흐름에 맞고 단순하다. 뺀 안: 다음 장으로 이어 읽기(책 끝까지 끊기지 않지만, 장을 끝냈는지 볼 틈이 없다), 설정으로 고르기(더 복잡하다).
- **완료 표시 방식**: 사용자가 직접 체크할 때만 완료가 된다. 장 목록의 체크와 본문 끝의 "이 장 학습 완료" 버튼으로 켜고, 다시 눌러 끌 수 있다(추천안·사용자 승인, 2026-11-08). 뺀 안: 본문 끝까지 스크롤하면 자동 완료. 읽기만 한 장도 완료로 잡힌다.
- **넓혀 보기로 더한 것**(쓰는 사람 관점·비슷한 제품 조사 서브에이전트, 2026-11-08): 사용자가 둘 다 골랐다.
  - 고른 것: 문장 이동과 단축키(이전·다음 문장, 문장을 눌러 거기서부터 읽기, 넷플릭스 패널과 같은 키), 따라 말하기(현재 문장 반복, 문장마다 자동 멈춤).
  - 질문 없이 요구사항에 넣은 것(기능을 쓰는 데 꼭 필요하다고 봤다): 본문 끝의 완료·다음 장 버튼, 영어 음성만 보이기와 영어 기기 음성이 없을 때 안내, 이미 저장한 책의 글자 수 채우기, 사용자가 스크롤하면 자동 스크롤 멈추기, 크롬 내장 음성의 알려진 문제 피하기.
  - 보였지만 질문에 넣지 않은 후보: 마지막으로 들은 문장 기억, 단어를 문맥과 함께 모아 복습하기. "넣지 않는 것"에 적었다.
- **검토**: `review-spec` 검토 없이 바로 구현한다(추천안·사용자 승인, 2026-11-08). 이유: 범위가 작고 외부 서비스·비용이 없다. 빠진 것은 구현 뒤 마지막 검증에서 잡는다. 뺀 안: 검토 뒤 구현(시간과 비용이 더 든다).
- **작업 브랜치**: `study-progress-tts`에서 구현하고, 사용자가 결과를 확인해 승인하면 main에 머지하고 push한다(앞 명세서와 같은 방식).

### 기존에 정해진 것 (다시 묻지 않는다)

- 원서 리더는 같은 확장 프로그램 안의 탭 화면이고, 데이터는 공통 저장소(`chrome.storage.local`)에 둔다. 저장 키·백업 방식은 `docs/specs/20261107-2252-book-reader/spec.md`와 `DEVELOPMENT.md`의 "저장 데이터 구조"를 따른다.
- 화면은 `docs/design.md`를 따른다. 확장 프로그램 권한은 `storage`, `unlimitedStorage`뿐이고 더하지 않는다.
- PC 크롬만 지원한다. 모바일, 다크 모드는 하지 않는다.
- 프로젝트 규칙: README·DEVELOPMENT를 고치면 한국어·영어 두 파일을 함께 고친다. 커밋 메시지는 영어로 쓴다. 테스트·스크린샷에는 직접 쓴 글이나 퍼블릭 도메인 글만 쓴다.

### 제약

- 기존 개발 도구와 검증 명령(`npm run typecheck`, `npm run lint`, `npm run test:run`, `npm run build`, `npm run check:build`), CI(`.github/workflows/ci.yml`)를 따른다.
- `check:build`의 외부 로드 검사(fetch, XHR, WebSocket, 외부 script·CSS)는 그대로 통과해야 한다. `speechSynthesis`는 이 검사에 걸리지 않는 브라우저 기능이다.

## 3. 범위

### 넣는 것

1. 장별 학습 완료 체크(4.1)
2. 책 학습 진행률과 이어 읽기 표시(4.2)
3. 소리 내어 읽기: 재생 조작, 음성·속도, 읽는 문장 표시(4.3)
4. 온라인 음성 설정(4.4)
5. 데이터: 백업 포함, 책 삭제 시 함께 지우기(4.5)
6. 화면, 문서, 검증(4.6)

### 넣지 않는 것

- 유료 음성 API: 위 결정.
- 넷플릭스 학습 패널의 소리 내어 읽기: 넷플릭스는 영상 소리가 있다.
- 메모 모아 보기의 소리 내어 읽기: 원서 리더에서 문장을 읽는 기능만 둔다. 모아 보기의 메모는 "원래 위치로"로 리더에 가서 들을 수 있다.
- 마지막으로 들은 문장 기억: 이어 읽기(읽던 문단)로 충분하다. 넓혀 보기 후보였다.
- 단어를 문맥 문장과 함께 모아 복습하기(단어장, 간격 반복): 넓혀 보기 후보였지만 이번 범위가 아니다.
- 넷플릭스 학습 대시보드에 원서 진행률 보이기: 원서 리더 안에서만 보인다.
- `chrome.tts` API: `tts` 권한이 새로 필요하다. 권한을 더하지 않는다.
- 단계별 학습 체크리스트, 날짜별 학습 기록·통계: 위 결정.
- 읽는 단어 하나하나 표시: 음성마다 단어 위치 신호가 다르므로 문장 단위로 표시한다.
- 소리 파일(mp3 등) 내려받기: 내장 음성은 소리 파일을 만들지 않는다.

## 4. 요구사항

### 용어

- **사용자**, **공통 저장소**, **원서 리더**, **메모**: 앞 명세서와 같다.
- **학습 완료**: 사용자가 한 장에 붙인 완료 표시. 장마다 켜짐/꺼짐 둘 중 하나다.
- **학습 진행률**: 책 전체 글자 수 가운데 학습 완료한 장의 글자 수 비율.
- **소리 내어 읽기**: 브라우저 내장 음성으로 원서 본문을 읽어 주는 기능.
- **기기 음성 / 온라인 음성**: 2장 결정의 뜻. Web Speech API의 음성 정보로 구분한다(구분 방법은 AI 재량).

### 4.1 장별 학습 완료

- **4.1-1** 리더의 장 목록에 장마다 학습 완료 체크가 있고, 본문 끝에 "이 장 학습 완료" 버튼과 "다음 장" 버튼이 있다(마지막 장에는 "다음 장"이 없다). 완료한 장의 본문 끝 버튼은 완료를 끄는 버튼으로 바뀐다. 누르면 바로 저장되고, 화면을 다시 열어도 그대로다. 장 목록에서 완료한 장은 완료 표시(초록)로 구별된다.
  - 확인: 통합 테스트로 장 셋인 책에서 (a) 장 목록의 둘째 장 체크를 켜고 다시 렌더링하면 켜져 있는지, (b) 본문 끝 버튼으로 첫 장을 켜고 끄면 저장소에 반영되는지, (c) 둘째 장 본문 끝의 "다음 장"을 누르면 셋째 장이 열리고 셋째 장에는 "다음 장"이 없는지 본다.
- **4.1-2** 학습 완료는 사용자가 직접 켜고 끌 때만 바뀐다. 본문 끝까지 스크롤하거나 끝까지 소리 내어 읽어도 바뀌지 않는다. 완료를 켜고 꺼도 읽던 위치와 메모는 바뀌지 않는다.
  - 확인: 통합 테스트로 끝까지 스크롤(읽던 위치 저장)과 끝까지 읽기(가짜 음성) 뒤 완료가 꺼져 있는지, 완료를 켜고 끈 뒤 읽던 위치와 메모가 그대로인지 본다.
- **4.1-3** 같은 책을 두 탭에서 열고 서로 다른 장의 완료를 번갈아 바꿔도, 다른 탭이 바꾼 장의 완료가 지워지지 않는다(앞 명세서 4.1-6과 같은 규칙).
  - 확인: 통합 테스트로 두 저장 경로에서 서로 다른 장의 완료를 번갈아 켜도 둘 다 남는지 본다.
- **4.1-4** 완료를 저장하지 못하면(저장소 오류) "저장하지 못했습니다" 안내가 보이고, 화면의 체크 상태가 저장소와 어긋난 채 남지 않는다.
  - 확인: 통합 테스트로 저장소 쓰기 실패를 흉내 내면 안내가 보이고 체크가 저장소 값과 같은지 본다.

### 4.2 학습 진행률과 이어 읽기

- **4.2-1** 학습 진행률은 (학습 완료한 장의 글자 수 합) ÷ (책 전체 글자 수)를 백분율로 보인다. 소수점은 버리고, 모든 장을 완료했을 때만 100%다. 전체 글자 수가 0인 책은 0%다. 표시는 "45% · 12장 중 5장 완료"처럼 장 수를 함께 쓴다.
  - 확인: 단위 테스트로 길이가 다른 장들(예: 짧은 머리말과 긴 장)에서 값이 글자 수 기준인지, 99.9%가 99%로 나오는지, 모두 완료일 때만 100%인지, 장이 없거나 글자가 없는 책이 0%인지 본다.
- **4.2-2** 책 목록에 책마다 진행 막대와 위 문구가 보이고, 리더(장 목록 위 또는 머리말)에도 같은 진행률이 보인다. 리더에서 완료를 바꾸면 리더의 진행률이 바로 바뀌고, 책 목록으로 돌아가면 바뀐 값이 보인다.
  - 확인: 통합 테스트로 완료를 바꾼 뒤 리더와 책 목록의 진행률 문구가 맞는지 본다.
- **4.2-3** 책 목록의 지금 "N/M장"(마지막으로 읽던 장)은 "이어 읽기: N장 〈장 이름〉"으로 바꾼다. 읽은 적 없으면 "아직 읽지 않음"이다. 진행률과 다른 줄에 보여 헷갈리지 않게 한다.
  - 확인: 통합 테스트로 읽던 위치가 있는 책과 없는 책의 문구를 본다. 기존 `BookList.test.tsx`의 "N/M장" 기대값은 이 요구사항에 맞춰 바꾼다(명세서가 바꾼 동작이다).
- **4.2-4** 이 기능 전에 등록한 책과, 예전 백업 파일에서 가져온 책도 진행률이 맞다. 책 목록을 열 때마다 모든 장의 본문을 읽지 않는다(글자 수를 한 번 구해 두고 쓴다. 방식은 AI 재량).
  - 확인: 통합 테스트로 글자 수 정보가 없는 예전 모양의 책을 넣고 책 목록과 리더의 진행률이 맞는지 본다. 같은 책 목록을 두 번째 열 때 장 본문 키를 읽지 않는지 저장소 읽기를 세어 본다.

### 4.3 소리 내어 읽기

- **4.3-1** 리더에 읽기 도구가 있다: 재생, 일시정지, 정지, 이전·다음 문장, 속도, 음성 고르기, 문장 반복, 문장마다 멈춤. 문단마다 "여기서부터 읽기"가 있다. 재생은 일시정지한 문장부터, 처음이면 읽던 위치의 문단부터 읽는다. 읽는 중에 본문의 문장을 누르면(글을 고르지 않은 클릭) 그 문장부터 읽는다. 하이라이트를 누르면 지금처럼 메모 영역이 열린다.
  - 확인: 통합 테스트(가짜 `speechSynthesis`)로 둘째 문단의 "여기서부터 읽기"를 누르면 첫 발화가 둘째 문단의 첫 문장인지, 일시정지 뒤 재생하면 같은 문장부터인지, 읽는 중 셋째 문장을 누르면 셋째 문장부터인지, 하이라이트를 누르면 메모 영역이 열리고 읽는 위치는 그대로인지 본다.
- **4.3-2** 문장 단위로 끊어 읽는다. 한 문장이 길면(기준 길이는 AI 재량) 쉼표·세미콜론·대시 등에서 더 나눈다. 흔한 약어(Mr., Mrs., Dr., St., e.g., i.e. 등), 소수점, 말줄임표, 따옴표 안의 마침표에서 잘못 끊지 않는다.
  - 확인: 단위 테스트로 위 각 경우와 정상적으로 끊어야 하는 경우(마침표·물음표·느낌표 뒤 대문자)를 본다.
- **4.3-3** 지금 읽는 문장을 본문에 현재 문장 색(`docs/design.md`의 "현재 문장")으로 보인다. 하이라이트·메모 표시를 가리지 않고 함께 보인다. 읽는 문장이 화면 밖으로 나가면 자동으로 스크롤한다. 사용자가 직접 스크롤하면 자동 스크롤을 멈추고 "읽는 곳으로" 버튼을 보이며, 누르면 그 문장으로 돌아가 다시 따라간다.
  - 확인: 통합 테스트로 둘째 문장 발화가 시작되면 둘째 문장에 표시가 붙고 첫 문장에서 빠지는지, 하이라이트가 있는 문장에서도 `mark`가 그대로인지, `scrollIntoView`가 불리는지, 사용자 스크롤 뒤에는 불리지 않고 버튼이 보이는지, 버튼을 누르면 다시 불리는지 본다.
- **4.3-4** 장 끝(마지막 문장 뒤)에서 읽기를 멈춘다. 읽기 도구에 "다음 장 읽기"가 보이고, 누르면 다음 장을 열어 처음부터 읽는다. 마지막 장에서는 보이지 않는다.
  - 확인: 통합 테스트로 마지막 문장이 끝나면 더 읽지 않는지, "다음 장 읽기"로 다음 장 첫 문장이 읽히는지 본다.
- **4.3-5** 원서 본문에서 글을 고르면 하이라이트 도구막대에 "읽기"가 있고, 누르면 고른 글만 읽고 멈춘다. 도구막대는 넷플릭스 학습 패널과 같은 부품이지만, 넷플릭스 학습 패널의 도구막대는 지금 그대로다("읽기"가 없다).
  - 확인: 통합 테스트로 고른 글이 발화되고 그 뒤 더 읽지 않는지 본다. 기존 `SentenceList.test.tsx`의 도구막대 테스트로 넷플릭스 쪽에 "읽기"가 없는지 본다.
- **4.3-6** 속도는 0.5배~2배에서 고르고, 음성과 속도, 문장 반복·문장마다 멈춤 켜짐은 저장되어 다시 열어도 유지된다. 저장한 음성을 찾을 수 없으면(지워졌거나 설정이 꺼짐) 기본 영어 기기 음성으로 읽고, 저장한 음성 설정은 지우지 않는다. 음성 목록이 화면을 연 뒤에 늦게 채워져도 목록과 저장한 음성에 반영된다.
  - 확인: 통합 테스트로 속도·음성을 바꾸고 다시 렌더링하면 같은지, 발화의 `rate`와 `voice`가 고른 값인지, 저장한 음성이 없으면 기본 영어 기기 음성으로 읽고 설정이 남는지, 음성 목록이 나중에 채워지는 경우(`voiceschanged`)를 본다.
- **4.3-7** 음성 목록에는 영어 음성만 보인다. 쓸 수 있는 영어 음성이 없으면 재생 대신 안내가 보인다: macOS 설정에서 영어 음성을 내려받거나 온라인 음성을 켜라는 안내다. 브라우저에 `speechSynthesis`가 없으면 읽기 도구 대신 "이 브라우저에서는 소리 내어 읽기를 쓸 수 없습니다"를 보인다.
  - 확인: 통합 테스트로 한국어 음성만 있는 경우, 음성이 없는 경우, `speechSynthesis`가 없는 경우의 안내를 본다.
- **4.3-8** 크롬 내장 음성의 알려진 문제를 피한다.
  - (a) 정지, 일시정지, 다른 곳에서 읽기 시작, 장 바꾸기를 하면 앞 읽기의 끝 신호 때문에 다음 문장이 이어 읽히지 않는다.
  - (b) 한 문장을 읽기 시작한 뒤 그 문장 길이에 비해 오래(기준은 AI 재량) 끝 신호가 없으면 멈춘 것으로 보고 그 문장부터 다시 읽는다. 온라인 음성은 긴 글을 읽다 끝 신호 없이 멈추는 일이 있다.
  - (c) 일시정지 뒤 다시 재생하면 그 문장 처음부터 읽는다.
  - (d) 장을 바꾸거나 다른 화면(책 목록, 모아 보기)으로 가거나 탭을 닫으면 읽기를 멈춘다.
  - (e) 읽는 문장 표시는 음성의 단어 위치 신호에 기대지 않는다(음성마다 신호가 다르다).
  - 확인: 단위·통합 테스트(가짜 `speechSynthesis`와 가짜 타이머)로 각 경우를 본다. (b)는 끝 신호를 보내지 않는 가짜 음성으로 본다.
- **4.3-9** 단축키(넷플릭스 학습 패널과 같은 키): `Space` 재생/일시정지, `A` 이전 문장, `S` 현재 문장 처음부터, `D` 다음 문장, `Q` 문장마다 멈춤 켜기/끄기, `R` 문장 반복 켜기/끄기. 입력칸, 메모 영역, 고르기 상자에서 글을 쓰거나 고르는 동안에는 동작하지 않는다. `Space`는 버튼에 포커스가 있어도 그 버튼을 다시 누르지 않는다.
  - 확인: 통합 테스트로 각 키가 해당 동작을 하는지, 메모 입력칸과 검색칸에서 누르면 동작하지 않는지, 버튼에 포커스가 있을 때 `Space`가 버튼을 누르지 않는지 본다.
- **4.3-10** 따라 말하기: "문장 반복"을 켜면 현재 문장을 끌 때까지 반복한다. "문장마다 멈춤"을 켜면 문장 하나를 읽고 멈추며, 재생이나 `D`로 다음 문장을 읽는다. 둘 다 켜짐을 초록으로 보인다.
  - 확인: 통합 테스트로 반복을 켜면 같은 문장이 다시 발화되는지, 멈춤을 켜면 한 문장 뒤 더 읽지 않고 재생으로 다음 문장이 읽히는지 본다.

### 4.4 온라인 음성 설정

- **4.4-1** 기본은 기기 음성만 목록에 보인다. 리더의 읽기 설정에 "온라인 음성도 쓰기"가 있고, 그 옆에 "켜면 읽는 글이 외부(Google 등) 서버로 전송됩니다"를 적는다. 켜면 온라인 음성이 "(온라인)" 표시와 함께 목록에 나온다. 이 설정은 저장되어 다시 열어도 유지되고, 처음에는 꺼져 있다.
  - 확인: 통합 테스트로 기기·온라인 음성이 섞인 가짜 목록에서 처음에는 기기 음성만 보이는지, 켜면 온라인 음성이 표시와 함께 보이는지, 다시 렌더링해도 켜져 있는지 본다.
- **4.4-2** 설정이 꺼져 있으면 어떤 경로(저장한 음성, 재생, 단축키, 고른 글 읽기, 다음 장 읽기)로도 온라인 음성으로 읽지 않는다. 온라인 음성을 고른 뒤 설정을 끄면 기본 영어 기기 음성으로 바뀐다.
  - 확인: 통합 테스트로 저장한 음성이 온라인 음성이고 설정이 꺼진 상태에서 각 경로의 발화가 모두 기기 음성인지 본다. 닮은 정상 경우로, 설정이 켜져 있으면 그 온라인 음성으로 읽는지도 본다.

### 4.5 데이터

- **4.5-1** 학습 완료 기록과 읽기 설정(음성, 속도, 온라인 음성 허용, 반복·멈춤)은 백업 내보내기에 들어간다. 가져올 때 같은 책 같은 장의 완료 기록은 나중에 바꾼 쪽이 남고, 파일에만 있는 것은 더해진다. 이 기능 전에 내보낸 백업(완료 기록과 읽기 설정이 없음)도 오류 없이 가져와지고, 지금의 완료 기록과 읽기 설정은 그대로 남는다. 형식이 틀린 완료 기록이 든 파일은 앞 명세서 4.6-3처럼 아무것도 바꾸지 않고 무엇이 문제인지 알린다.
  - 확인: 단위 테스트로 내보낸 내용에 완료 기록과 읽기 설정이 있는지, 겹치는 장(파일 쪽이 최근 / 지금 쪽이 최근)의 합치기, 예전 백업 가져오기, 형식이 틀린 완료 기록을 본다.
- **4.5-2** 책을 지우면 그 책의 완료 기록과 글자 수 정보도 함께 지운다. 다른 책의 기록은 남는다. 삭제 확인 문구는 지금과 같다.
  - 확인: 통합 테스트로 책 둘에 완료 기록이 있을 때 한 책을 지우면 그 책 것만 저장소에서 사라지는지 본다.
- **4.5-3** 넷플릭스 페이지 쪽 메시지(앞 명세서 4.1-4)로 완료 기록과 읽기 설정을 읽거나 쓰거나 지울 수 없다.
  - 확인: 단위 테스트로 그런 요청이 무시되고 저장소가 바뀌지 않는지 본다.
- **4.5-4** 외부로 나가는 것은 사용자가 켠 온라인 음성으로 읽는 글뿐이다. 그 밖의 외부 로드·전송 검사(`npm run check:build`)는 그대로 통과한다.
  - 확인: `npm run check:build`가 통과하고, 4.4-2 테스트가 통과한다.

### 4.6 화면, 문서, 검증

- **4.6-1** 화면은 `docs/design.md`를 따른다. 기준에 없는 부품(진행 막대, 읽기 도구, 읽기 설정)은 기준의 색·간격·모서리로 만들고 `docs/design.md`의 컴포넌트 절에 더한다. 완료 표시는 "켜짐(초록)", 읽는 문장은 "현재 문장" 색을 쓴다. 설정 메뉴나 고르기처럼 상호작용이 있는 부품은 키보드와 스크린 리더 처리가 된 기본 요소나 검증된 부품을 쓴다.
  - 확인: `design-check` 깨끗한 회차(기준 대조 포함). 폭은 1024px, 1280px, 1440px이다. 상태는 다음과 같다.
    - 책 목록: 진행률 0%, 중간, 100%가 섞인 경우, 이어 읽기가 없는 책.
    - 리더: 완료한 장이 섞인 장 목록, 읽는 중(문장 표시), 일시정지, 반복·멈춤 켜짐, 읽기 설정 열림(온라인 음성 꺼짐·켜짐), 영어 음성 없음 안내, 완료 저장 실패.
- **4.6-2** 완료 체크, 읽기 도구, 읽기 설정을 모두 키보드로 쓸 수 있고 포커스가 보인다. 버튼에는 이름이 있다(재생 중이면 "일시정지"처럼 상태에 맞게).
  - 확인: `design-check` 키보드 점검과 깨끗한 회차.
- **4.6-3** 개발용 화면(`reader-dev.html`)에서 가짜 음성(기기 음성 있음, 온라인 음성만, 음성 없음)으로 읽기 화면을 띄울 수 있다. 가짜 음성은 개발 빌드에만 들어가고 `npm run build` 결과물에 들어가지 않는다. 데모 시드에 완료한 장이 섞인 책이 있다.
  - 확인: 개발 서버로 `design-check`를 돌린다. `npm run check:build`가 `build/`에 가짜 음성의 표시 문자열(AI가 정함)이 없는지 본다.
- **4.6-4** 성능: 앞 명세서의 측정 데이터(책 20권, 한 권 200만 자, 메모 5,000개)에서 (a) 진행률이 들어간 책 목록이 1초 안에 보이고, (b) 20만 자 장에서 "여기서부터 읽기"를 누른 뒤 첫 발화 요청까지 0.5초 안이며, (c) 앞 명세서의 세 측정(미리 보기 3초, 장 열기 1초, 검색 0.5초)이 그대로 통과한다.
  - 확인: `scripts/perf/measure.mjs`에 (a)(b)를 더해 개발 서버와 Playwright로 재고 결과 보고서에 적는다. jsdom 단위 테스트로는 시간을 재지 않는다.
- **4.6-5** 문서를 고친다. README·README.en에 학습 완료·진행률, 소리 내어 읽기(단축키 표, 온라인 음성 설정과 전송 안내, macOS에서 고품질 영어 음성을 받는 방법)를 더한다. DEVELOPMENT·DEVELOPMENT.en에 새 저장 데이터, 가짜 음성으로 개발 화면 띄우기를 더한다. 두 언어 파일의 절 구성이 같다.
  - 확인: 고친 문서에 위 항목이 있는지, 두 언어 파일의 절 구성이 같은지 본다.
- **4.6-6** 지금 기능은 그대로 동작한다(원서 등록·읽기·메모·모아 보기·백업, 넷플릭스 학습 패널).
  - 확인: 기존 테스트 전체가 통과한다. 기대값을 바꾼 테스트는 이 명세서가 바꾼 동작(4.2-3)뿐이고, 그 이유를 진행 기록에 적는다.
- **4.6-7** 테스트·시드·스크린샷의 책 본문은 직접 쓴 글이나 퍼블릭 도메인 글만 쓴다.
  - 확인: 진행 기록에 출처를 적고, `npm run check:build`의 추적 파일 검사가 통과한다.

## 5. 완료 정의

### AI가 확인하고 끝낸다

- 4장의 모든 요구사항이 확인을 통과했다("사용자가 마지막에 확인한다"로 둔 부분은 그 전까지 AI가 할 일을 끝냈다).
- `npm run typecheck`, `npm run lint`, `npm run test:run`, `npm run build`, `npm run check:build`가 로컬에서 통과하고, `study-progress-tts` 브랜치 마지막 커밋의 CI가 성공했다.
- 바뀐 화면이 `design-check` 깨끗한 회차를 통과했고 시각 회귀 테스트로 남았다.
- 결과 보고서에 적을 것(이 문서만의 항목): 4.6-4 측정값, 이미 저장한 책의 글자 수를 어떻게 채우는지, 크롬 내장 음성 문제를 어떻게 피했는지(4.3-8), 확장 프로그램을 다시 불러오는 방법.

### 사용자가 마지막에 확인한다

1. `study-progress-tts` 브랜치에서 `npm run build` 뒤 `chrome://extensions`에서 이 확장 프로그램을 새로 고친다(ID는 바뀌지 않는다. 제거하지 않는다).
2. 이미 등록한 책에서 장 몇 개를 학습 완료로 켜고, 책 목록과 리더의 진행률이 맞아 보이는지 본다.
3. 기기 음성으로 한 장을 소리 내어 읽게 하고, 소리가 나는지, 읽는 문장 표시가 소리와 맞는지, 단축키와 따라 말하기가 쓸 만한지 본다. 자동 테스트는 가짜 음성으로 하므로 실제 소리는 사용자만 확인할 수 있다.
4. 읽기 설정에서 온라인 음성을 켜고 긴 장을 몇 분 읽게 해, 중간에 멈춘 채로 있지 않은지 본다(4.3-8 b).

## 7. 진행 규칙

- 작업 브랜치: `study-progress-tts`. main에 직접 커밋하지 않는다.
- 머지: 사용자가 `review-done`에서 통과와 머지를 승인하면 `study-progress-tts`를 main에 머지하고(fast-forward가 되면 fast-forward, 아니면 머지 커밋) origin/main에 push한다. 머지 뒤 main의 CI가 성공하는지 본다.

### 사전 승인

- `study-progress-tts` 브랜치를 origin에 push한다. 횟수 제한 없음.
- 개발용 npm 패키지 설치(devDependencies). 런타임 의존성은 꼭 필요할 때만 더하고 이유를 진행 기록에 적는다.
- 비용이 드는 일: 없음.

### 멈추고 물을 것

- `storage`, `unlimitedStorage` 말고 다른 권한(`tts` 포함)이 꼭 필요하다고 판단될 때.
- 사용자가 켠 온라인 음성 말고, 원서 본문이나 메모를 외부로 보내야 할 때.
- 공통 저장소의 기존 데이터(책, 메모, 읽던 위치)를 지우거나 모양을 바꿔야만 요구사항을 만족할 수 있을 때. 새 정보(완료 기록, 글자 수)를 더하는 것은 묻지 않는다.
- main에 직접 push하거나 force push가 필요할 때.
- 요구사항끼리 부딪쳐 둘 다 만족할 수 없을 때.
