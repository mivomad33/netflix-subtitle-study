# 여러 기기 동기화(Firebase)

- 작성일: 2026-11-08
- 요약: Google 계정으로 로그인하고, 학습 기록(메모, 학습 완료, 읽던 위치, 설정, 넷플릭스 학습 기록)과 원서 본문을 Firestore 한곳에 저장해 여러 PC의 크롬에서 학습을 이어 하게 한다.
- 종류: 변경 건(로컬에만 저장하던 확장 프로그램의 저장소를 Firestore로 바꾼다)
- 단계: 나누지 않는다. 이 명세서 하나로 끝낸다(`docs/plan.md` 없음, 2장 결정).
- 이 문서는 기획과 요구사항만 담는다. 설계와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 저장소 `mivomad33/netflix-subtitle-study`는 GitHub **공개 저장소**다. 커밋하는 모든 것은 공개된다. Firebase 웹 설정 객체(apiKey 등이 든 설정 파일)는 비밀 값이 아니지만 저장소에는 커밋하지 않는다(2장 결정). 프로젝트 id와 그것이 든 주소는 커밋해도 된다. 빌드 결과에는 들어간다. 데이터 보호는 보안 규칙이 맡는다.

## 1. 목표

### 지금 상태

- 메모, 책·본문, 읽던 위치, 학습 완료, 설정은 모두 그 PC 크롬의 `chrome.storage.local`에만 있다. 다른 PC에서는 백업 파일을 내보내고 가져와야 이어 할 수 있다.
- 백업 가져오기는 키마다 `updatedAt`이 더 새 쪽을 남기며 합치고, 아무것도 지우지 않는다.

### 바꾸려는 이유

- 여러 곳에서 여러 기기로 학습을 이어 하고 싶다(사용자, 2026-11-08).
- 나중에 유료 기능을 붙일 수 있게 사용자 계정을 두고 싶다. 지금은 모두 무료다(사용자, 2026-11-08).

### 쓰는 사람

- Google 계정이 있는 누구나(2장 결정). 지금은 사용자 본인이 여러 PC에서 쓴다. 소스를 받아 직접 빌드하는 다른 사람은 자기 Firebase 프로젝트를 만들어 그 설정값으로 빌드한다(2장 결정). Chrome 웹 스토어에는 올리지 않는다(지금과 같다).
- 예상 규모: 사용자 수십 명 이하. 1GiB 무료 저장에 20MB 상한이면 약 50명이다. 사용자가 늘어 하루 한도에 자주 걸리면 Blaze를 다시 본다(2장 결정).

### 어느 수준이면 충분한가

- 한 PC에서 바꾼 것은 다른 PC에서 그 화면을 새로 열면 보인다. 이미 열려 있는 화면에도 10초 안에 반영된다(지금 두 탭 사이에 반영되는 것과 같은 모양).
- 지금 있는 기능은 로그인한 뒤 모두 지금처럼 동작한다.

## 2. 확정된 결정과 제약

### 이 명세서 전에 정한 것

- **Firebase를 쓴다**(사용자 결정, 2026-11-08). 이유: 사용자 계정을 두어 나중에 유료 기능(결제 상태를 계정에 붙이고 보안 규칙으로 강제)을 붙이기 쉽다. 뺀 안:
  - Google Drive 앱 전용 폴더: 서버 없이 0원이지만, 결제한 사용자만 쓰게 강제할 수 없다.
  - `chrome.storage.sync`: 전체 약 100KB, 키 512개 한도라 메모가 조금만 쌓여도 넘친다.
  - Supabase 무료 요금제: 1주일 쓰지 않으면 프로젝트가 일시정지된다.
- **지금은 모든 기능 무료**다. 유료 기능은 나중에 따로 정한다(사용자 결정, 2026-11-08).
- **원서 본문도 동기화한다.** 그 사용자 본인만 읽고 쓸 수 있고, 공유 기능은 만들지 않는다(사용자 결정, 2026-11-08). 이유: 새 기기에서 로그인만 하면 책과 학습을 이어 가게 하려고. 사용자가 넣은 글을 본인만 보게 보관하는 서비스는 흔한 모델이고, 공유가 없으면 저작권 위험이 낮다.
- **보안 규칙은 테스트로 확인하고, 탈퇴하면 그 사용자의 데이터를 모두 지우고, 저작권 신고 창구와 개인정보처리방침을 둔다**(사용자 결정, 2026-11-08).
- **운영 비용은 없거나 적게** 한다(사용자 결정, 2026-11-08).
- 앞 명세서의 "본문과 메모를 외부로 보내지 않는다"에, 사용자가 로그인했을 때 그 사용자의 Firebase 저장소로 보내는 예외를 둔다(사용자 결정, 2026-11-08).
- 읽기 음성은 기기 음성만 쓴다(2026-11-08 사용자 결정으로 온라인 음성을 뺐다). 이 명세서는 음성을 바꾸지 않는다.

### 이 명세서에서 정한 것

- **본문도 Firestore에 저장하고, Firebase는 무료 Spark 요금제로 둔다**(추천안·사용자 승인, 2026-11-08). 본문은 문서 한도(1MiB)에 맞게 나눠 저장한다.
  - 이유: Cloud Storage for Firebase는 2024년 9월 발표 이후 Blaze(사용량 과금, 결제 계정 연결)에서만 쓸 수 있다. Spark는 결제 수단이 없어 요금이 나올 수 없고, 한도를 넘으면 그날 요청만 막힌다.
  - 바뀐 결정: 처음 대화에서는 본문을 Cloud Storage에 두기로 했다(2026-11-08). 위 요금제 제약을 확인한 뒤 바꿨다.
  - 감수하는 것: Spark 한도는 모든 사용자 합계로 저장 1GiB, 하루 읽기 5만·쓰기 2만·삭제 2만이다(<https://firebase.google.com/docs/firestore/quotas>, 2026-11-08 확인).
  - 뺀 안: Cloud Storage + Blaze. 카드 등록이 필요하고 요금 상한이 없다. 유료 기능을 붙일 때 다시 본다.
  - 큰 결정 검토: 서로 다른 모델 셋이 각자 안을 냈고, 셋 다 Firestore + Spark를 냈다. 이 검토로 추천이 Cloud Storage에서 Firestore로 바뀌었다.
- **로그인은 Google 계정으로 한다**(추천안·사용자 승인, 2026-11-08). 크롬의 Google 계정 토큰으로 Firebase에 로그인하고, 그 밖의 로그인 수단은 두지 않는다.
  - 이유: 비밀번호를 따로 관리하지 않고 버튼 한 번으로 로그인한다.
  - 감수하는 것: 확장 프로그램 권한 `identity`와 `manifest.json`의 `oauth2` 항목을 새로 더한다. Google Cloud에 크롬 확장 프로그램용 OAuth 클라이언트를 등록한다. (아래 로그인 창 방식 결정으로 `oauth2` 항목과 크롬 확장 프로그램용 클라이언트는 쓰지 않게 바뀌었다.)
  - 뺀 안:
    - 이메일·비밀번호: 새 권한은 없지만, 비밀번호 관리와 가입·재설정 화면, 메일이 필요하다.
    - `signInWithPopup` + offscreen 문서: 공개 호스팅 페이지와 `offscreen` 권한, CSP 변경이 필요해 더 무겁다.
  - 큰 결정 검토: 셋 중 둘이 Google 로그인(`chrome.identity`), 하나가 이메일·비밀번호를 냈다.
- **Google 로그인은 로그인 창 방식(`chrome.identity.launchWebAuthFlow`)으로 한다**(추천안·사용자 승인, 2026-11-08. 위 결정의 "크롬의 Google 계정 토큰"을 바꿨다). Google 로그인 창에서 받은 ID 토큰으로 Firebase에 로그인한다.
  - 이유: 크롬 토큰 방식(`getAuthToken`)은 크롬 프로필 자체에 로그인해야 한다(<https://developer.chrome.com/docs/extensions/reference/api/identity>, 2026-11-08 확인). 크롬에 로그인하지 않은 PC에서도 쓰게 한다.
  - 바뀌는 것: 권한은 `identity` 하나만 더하고, `manifest.json`의 `oauth2` 항목은 두지 않는다. OAuth 클라이언트는 웹 애플리케이션 유형이고, 리디렉션 주소 `https://flhkacfjjpipfoicbnmednajnhebihmb.chromiumapp.org/`를 등록한다(6장).
  - 뺀 안: 크롬 토큰 방식(처음 승인한 안).
- **20MB 상한은 앱이 합계로 막고, 보안 규칙은 문서 하나와 글 하나의 크기를 막는다**(추천안·사용자 승인, 2026-11-08).
  - 이유: 보안 규칙은 컬렉션을 모아 셀 수 없어 사용자별 합계를 강제할 수 없다(<https://firebase.google.com/docs/firestore/security/rules-conditions>, 2026-11-08 확인). Cloud Functions는 Blaze가 필요하다.
  - 감수하는 것: 앱을 거치지 않고 API를 직접 부르는 사용자는 합계를 넘길 수 있다.
  - 뺀 안: 쓸 때마다 사용량 문서를 함께 고치고 규칙이 검사하기. 구현이 복잡하고 쓰기마다 읽기·쓰기가 늘어 무료 한도를 더 쓴다.
- **백업 내보내기·가져오기는 둘 다 유지한다**(추천안·사용자 승인, 2026-11-08). 내보내기는 Firestore에 있는 그 사용자의 데이터를 파일로 받고, 가져오기는 파일을 Firestore에 합친다(지금처럼 키마다 `updatedAt`이 새 쪽을 남기고 아무것도 지우지 않는다). 지금 버전에서 받은 백업 파일도 가져올 수 있다. 가져온 데이터도 20MB 상한에 든다. 이유: 옛 데이터를 지우기 전에 받은 백업을 되살릴 길이 되고, 개인정보 내보내기 요청에도 답할 수 있다. 뺀 안: 내보내기만, 둘 다 빼기.
- 열린 질문("걱정되는 것, 하면 안 되는 것, 이미 아는 함정")에 사용자는 "특별히 없음"이라고 답했다(2026-11-08).
- **데이터의 원본은 Firestore 하나다. 기기마다 사본을 두고 동기화하지 않는다**(사용자 결정, 2026-11-08).
  - 로그인해야 앱을 쓴다(넷플릭스 자막 학습 기능은 예외, 아래 2026-11-09 결정). 메모, 책·본문, 읽던 위치, 학습 완료, 설정, 넷플릭스 학습 기록을 모두 Firestore에서 읽고 Firestore에 쓴다.
  - 화면 속도를 위해 Firebase SDK의 자체 캐시(IndexedDB)는 쓴다. 이 캐시는 SDK가 관리하는 임시 사본이고, 직접 만든 동기화·합치기 코드는 두지 않는다.
  - 이유: 데이터가 한곳에만 있으면 동기화 버튼, 합치기 규칙, 삭제 표시, 첫 로그인 합치기, 로그아웃 처리 같은 문제가 거의 사라진다. 넷플릭스는 온라인에서만 보므로 오프라인은 고려하지 않는다.
  - 바뀐 결정: 처음에는 기기에 사본을 두고 자동으로 동기화하기로 했다(추천안·사용자 승인, 2026-11-08). 사용자가 원격 저장을 제안해 바꿨다.
  - 감수하는 것: 읽기도 무료 한도에 들어가고, 한도를 넘으면 그날은 앱이 열리지 않는다.
- **가입은 누구나 할 수 있다**(사용자 결정, 2026-11-08). Google 계정이 있으면 가입해 쓸 수 있다.
  - 감수하는 것: 무료 한도는 모든 사용자가 함께 쓴다. 다른 사용자가 많이 쓰면 그날 모두가 멈출 수 있다.
  - 뺀 안: 허용한 계정만(추천했던 안). 사용자가 누구나 쓰는 쪽을 골랐다.
- **사용자마다 저장 상한을 20MB로 둔다**(추천안·사용자 승인, 2026-11-08). 본문을 포함한 그 사용자의 데이터 합계다. 이유: 한 사람이 공유 무료 한도(1GiB)를 다 쓰지 못하게 한다. 1GiB에 약 50명이 들어간다. 뺀 안: 50MB(약 20명), 상한 없음.
- **기존 데이터는 옮기지 않고 처음부터 시작한다**(사용자 결정, 2026-11-08). 이 PC의 `chrome.storage.local`과 넷플릭스 사이트 `localStorage`에 있는 학습 기록을 Firestore로 올리지 않는다. 로그인한 뒤의 앱은 빈 상태에서 시작한다.
  - 뺀 안: 처음 로그인할 때 지금 PC의 데이터를 Firestore로 한 번 올리고 원래 데이터는 남겨 두기(추천했던 안). 사용자가 처음부터 시작하는 쪽을 골랐다.
- **두 단계로 나눈다**(추천안·사용자 승인, 2026-11-08). 1단계는 넷플릭스 사이트 `localStorage`의 학습 기록을 확장 프로그램 공통 저장소로 옮기고, 2단계는 공통 저장소를 Firestore로 바꾸는 안이었다.
  - 이 결정은 원격 저장과 "처음부터 시작" 결정으로 근거가 사라졌다. 옮길 데이터가 없고, 넷플릭스 기록도 처음부터 Firestore에 쓰면 되기 때문이다.
- **명세서 하나로 한다**(추천안·사용자 승인, 2026-11-08. 위 두 단계 결정을 바꿨다). 로그인, 본문을 포함한 모든 데이터의 Firestore 저장, 넷플릭스 기록, 탈퇴, 개인정보·저작권 안내를 이 명세서에서 한다.
  - 이유: 원격 저장이라 본문만 기기에 남기는 중간 단계를 만들 수 없다. 저장소를 한곳(StorageArea)으로 모아 둔 기존 구조라 바꿀 곳이 모여 있다.
  - 뺀 안: 학습 기록과 책·본문을 두 단계로 나누기. 1단계 동안 책 기능을 막거나 기기에 남겨야 한다.
- **업데이트 뒤 옛 데이터는 지운다**(사용자 결정, 2026-11-08). 이 확장 프로그램이 `chrome.storage.local`에 둔 데이터와, 넷플릭스 사이트 `localStorage`에 둔 이 확장 프로그램의 키를 지운다. 넷플릭스 자체의 키는 건드리지 않는다.
  - 감수하는 것: 지운 데이터는 되살릴 수 없다. 남기려면 업데이트 전에 지금 버전의 백업 내보내기로 받아 둔다.
  - 뺀 안: 그대로 두기(추천했던 안).
- **개인정보처리방침과 저작권 안내는 Firebase Hosting(`https://nf-subtitle-study-21cae.web.app/`)에 둔다**(추천안·사용자 승인, 2026-11-09). Spark에서 0원이고, Firebase CLI로 배포하며, 구글 로그인 공개 설정에 이 주소를 넣는다.
  - 이유: `nf-subtitle-study-21cae.web.app`은 이 Firebase 프로젝트의 기본 Hosting 사이트이고 Firebase Auth의 승인된 도메인에 이미 있다. 배포가 브랜치·머지와 묶이지 않는다. OAuth 브랜드 검증을 하지 않으므로(아래 결정) Search Console 소유 확인도 하지 않는다.

  - 뺀 안: 브랜드 검증까지 받기.

- 사용 통계는 모으지 않는다. Firebase Analytics 등 분석 도구를 붙이지 않는다(AI 판단, 2026-11-08. 개인정보처리방침을 작게 유지한다).
- **Firebase는 무료 Spark 요금제를 유지한다**(추천안·사용자 승인, 2026-11-08). 하루 한도에 걸리면 그날은 저장하는 기능이 멈추고, 무료 사용량을 다 썼다고 안내한다(넷플릭스 자막 학습 기능은 저장소 오류가 나도 기본 설정으로 계속 동작한다). 사용자가 늘면 그때 Blaze를 다시 본다. 뺀 안: Blaze + 예산 알림(카드 등록이 필요하고, 예산 알림은 과금을 막지 못한다).

### 제약

- 크롬 확장 프로그램 Manifest V3다. 확장 프로그램 ID는 `manifest.json`의 `key`로 고정돼 있다(`flhkacfjjpipfoicbnmednajnhebihmb`).
- 확장 프로그램은 PC 크롬에서만 돈다. 휴대폰·태블릿은 이번 대상이 아니다.
- 넷플릭스 페이지의 코드는 `chrome.*`를 쓸 수 없고, content script와 검증된 메시지로만 저장소를 쓴다(앞 명세서의 브리지). 넷플릭스 쪽에 계정 정보나 다른 데이터가 새로 노출되면 안 된다.
- 그래서 Firebase SDK(Auth·Firestore)는 확장 프로그램 출처(서비스 워커, 확장 프로그램 화면)에서만 돈다. content script는 넷플릭스 출처라 그 IndexedDB·localStorage를 넷플릭스 페이지가 읽을 수 있으므로, content script에서는 Firebase를 쓰지 않고 메시지로 중계만 한다(4.3-4).

## 4. 요구사항

용어

- **사용자**: Google 계정으로 로그인한 사람. Firebase 사용자 id(uid)로 구별한다.
- **운영자**: Firebase 프로젝트 소유자(`hunt24333@gmail.com`). 관리자 화면은 없고 Firebase 콘솔을 쓴다.
- **확장 프로그램 화면**: 원서 리더, 메모 모아 보기, 팝업 등 `chrome-extension://` 주소의 화면.
- **넷플릭스 화면**: 넷플릭스 페이지에 넣은 학습 패널과 대시보드.
- **운영 프로젝트**: 6장에서 만든 실제 Firebase 프로젝트. **에뮬레이터**: Firebase Local Emulator Suite(실제 프로젝트 없이 `demo-`로 시작하는 프로젝트 id로 돈다).
- 확인의 "단위"는 Vitest+jsdom, "통합"은 에뮬레이터에 붙는 Vitest 테스트, "E2E"는 빌드한 확장 프로그램을 Playwright로 띄우는 테스트다.

### 4.1 로그인

- **4.1-1** 확장 프로그램 화면에 "Google로 로그인" 버튼이 있고, 누르면 Google 로그인 창(`launchWebAuthFlow`, 범위 `openid email`)이 열린다. 계정을 고르면 Firebase에 로그인되고, 화면에 로그인한 계정의 이메일이 보인다.
  - 확인: 단위(가짜 로그인 창·가짜 Firebase Auth로 버튼 → 로그인 → 이메일 표시). 실제 Google 로그인은 AI가 할 수 없어 "사용자가 마지막에 확인한다".
- **4.1-2** 로그인하지 않았으면 원서 리더·메모 모아 보기가 데이터를 읽지도 보여 주지도 않고 로그인 안내를 보인다. 넷플릭스 학습 패널은 자막 학습 기능(이중 자막 목록, 오버레이, 자동 멈춤, 자막 처리)을 기본 설정으로 동작시키고, 메모·체크리스트·공부한 영상 목록·대시보드·설정 저장 자리에는 로그인 안내를 보이며 저장소를 읽거나 쓰지 않는다(2장 결정). 넷플릭스 화면의 안내는 확장 프로그램 화면을 여는 링크를 준다(넷플릭스 화면에서 직접 로그인하지 않는다).
  - 확인: 단위(로그아웃 상태에서 각 화면이 저장소를 부르지 않고 안내를 보이는지, 넷플릭스 패널의 자막 목록은 기본 설정으로 그려지는지, 로그인 상태에서는 데이터가 보이는지).
- **4.1-3** 로그인은 브라우저를 껐다 켜도 유지되고, 로그아웃할 때까지 남는다. 로그인 만료나 취소된 계정이면 로그인 안내로 돌아간다.
  - 확인: 단위(인증 상태 변화에 따라 화면이 바뀌는지). 브라우저 재시작 유지는 "사용자가 마지막에 확인한다".
- **4.1-4** 로그아웃하면 Firebase에서 로그아웃하고, Firestore SDK 캐시(IndexedDB)를 지운다(`terminate` 뒤 `clearIndexedDbPersistence`). 같은 PC에서 다른 계정으로 로그인하면 앞 계정의 데이터가 한 글자도 보이지 않는다.
  - 확인: Node에는 Firestore의 IndexedDB 캐시가 없으므로 브라우저에서 본다. E2E(빌드한 확장 프로그램을 에뮬레이터에 붙여 Playwright로 띄우고, 확장 프로그램 화면 둘을 연 채 계정 A로 쓰고 로그아웃 → IndexedDB의 Firestore 캐시가 비었는지, 계정 B로 로그인 → A의 데이터가 없는지). 에뮬레이터에 붙는 빌드 방식은 AI 재량.
- **4.1-5** 로그인 창을 닫거나 취소하면 오류 없이 로그인 전 화면으로 돌아가고 "로그인을 취소했습니다"류 안내를 보인다.
  - 확인: 단위(가짜 로그인 창이 취소를 돌려줄 때).

### 4.2 저장

- **4.2-1** 메모(넷플릭스·원서), 위치를 찾지 못한 넷플릭스 메모 목록(지금의 `meta:netflixUnplaced:*`, Firestore에 두되 바뀐 때만 쓰거나 메모리에만 두는 것은 AI 재량), 책 정보와 본문, 읽던 위치, 학습 완료, 원서 리더 설정, 넷플릭스 학습 기록(영상별 체크리스트·회차, 공부한 영상 목록, 페이지당 대사 수, 패널·재생·자막 설정)을 모두 그 사용자의 Firestore 영역에 읽고 쓴다. 로컬(`chrome.storage.local`, 넷플릭스 `localStorage`)에는 이 데이터를 쓰지 않는다(SDK 캐시, 2장의 자막 처리 값 둘, 4.7-1의 지운 표시는 예외).
  - 확인: 통합(각 종류를 쓰고 새 클라이언트로 읽으면 같은 값). 단위(저장 코드가 `chrome.storage.local.set`과 2장 예외 밖의 `localStorage.setItem`을 부르지 않는지 가짜 저장소로 확인).
- **4.2-2** 지금 있는 기능(메모 쓰기·고치기·지우기·검색, 책 가져오기·지우기, 장 읽기, 읽던 위치, 학습 완료·진행률, 소리 내어 읽기 설정, 넷플릭스 체크리스트·대시보드)은 로그인한 뒤 지금처럼 동작한다.
  - 확인: 기존 단위 테스트가 모두 통과한다(테스트용 메모리 저장소는 남겨도 된다). 통합(저장소를 Firestore 구현으로 바꿔 기존 저장소 테스트(`repo.test.ts` 등)와 같은 경우를 돌린다).
- **4.2-3** 한 곳(다른 PC나 다른 탭)에서 바꾼 것이 이미 열린 다른 화면에 10초 안에 반영된다. 새로 연 화면에는 바로 보인다. 같은 항목을 두 곳에서 고치면 나중에 쓴 쪽이 남는다.
  - 확인: 통합(두 클라이언트를 에뮬레이터에 붙여, 한쪽에서 쓰고 다른 쪽의 변경 알림이 10초 안에 오는지). 단위(넷플릭스 화면의 브리지가 변경 알림을 받아 화면에 넘기는지, 서비스 워커가 다시 깨어난 뒤에도 구독이 되살아나는지). 서비스 워커는 쉬면 30초 뒤 멈추므로, 열린 넷플릭스 패널이 서비스 워커가 멈춘 뒤에도 다른 클라이언트의 변경을 10초 안에 받는지 E2E(4.1-4의 에뮬레이터 틀에서 서비스 워커를 멈춘 뒤 다른 클라이언트에서 쓰기)로 본다.
- **4.2-7** 화면을 열 때 필요한 것만 읽는다. 본문 조각 전체나 모든 메모를 화면마다 다시 읽지 않도록 문서를 묶고 구독 범위를 좁힌다(하루 읽기 5만은 모든 사용자 합계다).
  - 확인: 통합(성능 시드 규모의 데이터로 빈 캐시 클라이언트가 각 화면을 열 때 서버에서 받은 문서 수(`fromCache`가 거짓인 것)를 세고, 하루 예상 읽기 수 계산과 함께 진행 기록에 적는다. 장 하나를 열 때 다른 장의 조각을 읽지 않는지 확인).
- **4.2-4** 큰 본문(장 하나가 문서 한도 1MiB를 넘는 경우 포함)도 저장하고 그대로 다시 읽는다.
  - 확인: 통합(1.5MiB 넘는 장을 쓰고 읽어 같은지, 책을 지우면 나눠 둔 조각도 모두 지워지는지).
- **4.2-5** 지금 있는 성능 기준(`scripts/perf/measure.mjs`의 여섯 시간)은 개발 화면에서 그대로 통과한다. 운영 프로젝트에서 장 열기는 SDK 캐시가 있을 때 1초 이하다.
  - 확인: `node scripts/perf/measure.mjs` 통과(개발 화면). 운영 프로젝트의 속도는 AI가 로그인할 수 없어 "사용자가 마지막에 확인한다".
- **4.2-6** 저장이 실패하면(권한 거부, 상한, 무료 한도 초과, 오래 연결되지 않음) 조용히 버리지 않고 4.4의 안내를 보인다. 연결이 잠깐 끊긴 동안의 쓰기는 SDK가 다시 보내도 된다.
  - 확인: 단위(가짜 저장소가 각 오류를 낼 때 안내가 보이는지).

### 4.3 넷플릭스 화면과 브리지

- **4.3-1** 넷플릭스 화면의 학습 기록과 설정은 지금처럼 content script를 거치는 브리지로 읽고 쓴다. 넷플릭스 화면은 넷플릭스 메모와 넷플릭스 학습 기록만 다룰 수 있고, 책·본문·원서 메모·계정 정보(이메일, uid, 토큰)는 받을 수 없다.
  - 확인: 단위(`handler.test.ts`에 더한다: 허용 작업은 통과, 책·원서 메모·계정 정보를 읽으려는 요청과 형식이 틀린 요청은 거부. 넷플릭스 메모와 닮은 원서 메모 id도 거부).
- **4.3-2** 넷플릭스 화면이 로그인 상태를 알아야 하면 "로그인됨/안 됨" 하나만 받는다. 브리지 오류 응답은 정해 둔 오류 종류 코드만 담고 원래 오류 문구(문서 경로에 uid가 들 수 있다)는 넘기지 않는다.
  - 확인: 단위(브리지 응답에 그 밖의 계정 필드가 없는지, 가짜 저장소가 uid가 든 문구로 실패할 때 브리지 응답에 그 uid가 없는지).
- **4.3-3** 넷플릭스 화면의 브리지 요청 형식 검사(같은 창·같은 출처·아는 작업·길이 상한)를 새 작업에도 지금과 같은 수준으로 둔다. 체크리스트·영상 목록 같은 새 값에는 크기 상한을 둔다.
  - 확인: 단위(상한을 넘는 값과 형식이 틀린 값은 거부, 상한 바로 아래 값은 통과).
- **4.3-4** Firebase SDK는 content script 번들(`contentLoader`, `contentScript` 등 넷플릭스 페이지에 들어가는 번들)에 들어가지 않는다(2장 제약).
  - 확인: `check:build`가 그 번들에서 Firebase 표지(예: `firestore.googleapis.com`, `identitytoolkit`)를 찾으면 실패하게 하고, 표지를 넣은 번들로 실패하는지 테스트.

### 4.4 상한과 오류 안내

- **4.4-1** 앱은 그 사용자의 저장량 합계를 알고, 쓰기 뒤 합계가 20MB(20×1024×1024바이트, 크기 계산 방식은 AI 재량이되 Firestore 저장 크기보다 작게 세지 않는다)를 넘는 쓰기는 보내지 않고 "저장 공간 20MB를 다 썼습니다"류 안내를 보인다. 원서 리더의 설정이나 백업 근처에 "사용량 n MB / 20MB"를 보인다.
  - 확인: 단위(상한 바로 아래로 끝나는 쓰기는 통과, 넘는 쓰기는 거부, 지운 뒤에는 다시 쓸 수 있음).
- **4.4-2** Firestore가 무료 한도 초과(`resource-exhausted`)를 돌려주면 "오늘 무료 사용량을 다 썼습니다. 한도는 태평양 시간 자정(한국 시간 오후 4시 또는 5시)에 다시 채워집니다"류 안내를 보이고, 다시 시도 버튼을 둔다.
  - 확인: 단위(가짜 저장소가 그 오류를 낼 때. 다른 오류에서는 이 안내가 나오지 않음).
- **4.4-3** 네트워크 끊김, 권한 거부, 로그인 만료는 서로 다른 안내를 보인다. 안내에 개인정보(이메일 외)와 내부 오류 문자열을 그대로 보이지 않는다.
  - 확인: 단위(오류 종류별 문구).
- **4.4-4** 로그인 확인, 첫 읽기처럼 오래 걸릴 수 있는 동작에는 대기 표시를 보인다.
  - 확인: 단위(대기 중 표시가 보이는지), 화면은 4.9.

### 4.5 보안 규칙

- **4.5-1** Firestore 보안 규칙은 로그인한 사용자가 자기 uid 영역만 읽고 쓰게 한다. 로그인하지 않은 요청, 다른 uid 영역, 자기 uid로 시작하지만 다른 uid(예: `abc`와 `abcd`) 영역, 영역 밖 경로는 모두 거부한다. 기본은 거부다.
  - 확인: 통합(`@firebase/rules-unit-testing`과 에뮬레이터. 허용과 거부 경우를 모두 테스트). 일부러 규칙을 모두 허용으로 바꾸면 거부 테스트가 실패하는지 한 번 보고 진행 기록에 적는다.
- **4.5-2** 규칙은 문서의 필드 수, 문자열 필드 하나의 길이, 목록 길이에 상한을 둔다(규칙은 문서의 바이트 크기를 직접 잴 수 없다. 값은 AI 재량. 앱이 쓰는 가장 큰 정상 문서는 통과해야 한다).
  - 확인: 통합(상한 바로 아래는 통과, 넘으면 거부).
- **4.5-3** 저장소의 규칙 파일이 운영 프로젝트에 배포된 규칙과 같다.
  - 확인: Firebase CLI에는 배포된 규칙을 내려받는 명령이 없다. 배포한 뒤 같은 명령(`firebase deploy --only firestore:rules`)을 한 번 더 돌려, 규칙이 이미 최신이라 올리지 않았다는 출력이 나오는지 본다(명령과 출력을 진행 기록에). CLI 인증 파일(`~/.config/configstore/firebase-tools.json`)은 읽지 않는다.

### 4.6 탈퇴

- **4.6-1** 확장 프로그램 화면에 "탈퇴(모든 데이터 지우기)"가 있다. 무엇이 지워지고 되살릴 수 없다는 것과 먼저 백업 내보내기를 권하는 확인 단계를 거친다(실수로 한 번 눌러 지워지지 않게). 확인하면 그 사용자의 Firestore 데이터를 모두 지운 뒤 Firebase 계정을 지우고, SDK 캐시도 지운다.
  - 확인: 통합(에뮬레이터에서 사용자 A, B의 데이터를 만들고 A가 탈퇴 → A의 문서가 0개, A의 Auth 사용자 없음, B의 데이터는 그대로). 단위(확인 단계 없이 지워지지 않음).
- **4.6-2** 계정 삭제에 최근 로그인이 필요하면 로그인 창으로 다시 인증한 뒤 이어 간다. 중간에 끊기면 다시 탈퇴를 누를 때 남은 데이터를 지우고 계정을 지운다(계정은 데이터를 다 지운 뒤 마지막에 지운다).
  - 확인: 통합(데이터 일부를 지운 뒤 실패시키고 다시 실행하면 끝까지 지워지는지).

### 4.7 옛 로컬 데이터 지우기

- **4.7-1** 업데이트한 확장 프로그램이 처음 돌 때 이 확장 프로그램이 `chrome.storage.local`에 둔 키(`memo:`, `book:`, `bookch:`, `pos:`, `done:`, `reader:settings`, `meta:`)를 지운다. 한 번만 하고, 다시 돌지 않게 표시를 남긴다.
  - 확인: 단위(그 키들은 지워지고, Firebase SDK나 지운 표시처럼 이 목록 밖의 키는 남는지).
- **4.7-2** 넷플릭스 화면이 열릴 때마다 넷플릭스 `localStorage`에서 이 확장 프로그램의 키(설정, `NF_checklist_*`, `NF_itemsPerPage_*`, `NF_studied_videos`, `NF_annotations_*` 등 [storageKeys.ts](../../../src/pages/Content/constants/storageKeys.ts)에 있는 키와 접두어)만 지운다. 그 목록에 없는 `NF_` 키는 남긴다. 2장의 자막 처리 값(`NF_lingoActive`, `NF_preferredTextLocale`)과 `NF_`로 시작하지 않는 넷플릭스 자체 키는 남긴다. 지운 표시는 남기지 않는다(새 코드는 이 키들을 쓰지 않으므로 매번 지워도 결과가 같다).
  - 확인: 단위(지울 키, 남길 키, 목록에 없는 `NF_` 키(예: `NF_other`), `NF_`와 닮은 넷플릭스 키(예: `nf_x`, `NFX`)를 넣은 가짜 `localStorage`).
- **4.7-3** 예전 메모 옮기기(`legacyMigration`, `ensureLegacyMigration`)는 없앤다. 옛 데이터를 옮기지 않는다는 결정 때문이다.
  - 확인: 코드 검색(관련 코드와 브리지 작업 `legacy.migrate`가 없음), 기존 테스트 정리 후 전체 테스트 통과.

### 4.8 백업과 공개 페이지

- **4.8-1** 백업 내보내기는 Firestore에 있는 그 사용자의 데이터를 지금과 같은 파일 형식(`nf-study-backup`)으로 받는다. 넷플릭스 학습 기록도 넣는다(형식 버전을 올려도 된다).

- **4.8-2** 백업 가져오기는 파일을 Firestore에 합친다(키마다 `updatedAt`이 새 쪽, `updatedAt`이 없는 항목은 지금 값이 있으면 지금 값을 남김, 아무것도 지우지 않음). 지금 버전(버전 1)의 파일도 받는다. 합친 뒤 20MB를 넘으면 가져오지 않고 안내한다.
  - 확인: 통합(지금 버전 파일 가져오기, 새 쪽 남기기, 상한 초과 거부).

### 4.10 빌드, 권한, 비밀 값

- **4.10-1** 권한은 `storage`, `unlimitedStorage`, `identity` 셋이고 `host_permissions`는 없다. `check:build`가 이것을 검사한다.
  - 확인: `npm run check:build` 통과. 권한을 하나 더한 manifest로는 실패하는지 테스트(`scripts` 테스트에 더한다).
- **4.10-2** 확장 프로그램 번들(서비스 워커 번들 포함)이 네트워크로 연결하는 외부 주소는 Firebase·Google 인증에 필요한 Google 도메인(목록은 AI가 정해 `check:build`에 둔다)과 4.8-4의 방침 링크 주소(`nf-subtitle-study-21cae.web.app`)뿐이다. 원격 코드(외부 스크립트 불러오기)는 없다. `check:build`의 외부 전송 검사를 이 기준으로 고친다. "연결"은 네트워크 호출 대상만 뜻한다. 화면 링크(예: 원서 리더의 `https://www.netflix.com` 영상 링크), 라이브러리의 오류 안내 주소, XML 이름공간처럼 연결하지 않는 문자열은 막지 않는다(판정 방법은 AI 재량). 지금 `fetch(`·`XMLHttpRequest`를 통째로 막는 검사는 Firebase SDK가 쓰므로 바꾼다.

- **4.10-3** 저장소와 빌드 결과에 서비스 계정 키, OAuth 클라이언트 보안 비밀, 사용자 데이터가 없다. Firebase 웹 설정값 파일은 커밋하지 않고 `.gitignore`에 둔다. Firebase CLI·에뮬레이터 로그(`firebase-debug.log`, `firestore-debug.log`, `ui-debug.log` 등)도 `.gitignore`에 둔다.
  - 확인: `check:build`에 서비스 계정 키 JSON 모양(`"private_key"`)과 `client_secret` 검사를 더한다. 검사 대상은 빌드 결과와 추적 파일이되, 이 문자열을 설명하거나 시험하는 문서(`docs/`), 테스트 파일, 검사 스크립트 자신은 뺀다. 그 문자열이 든 파일로 실패하는지 테스트. 설정 파일과 로그 파일이 무시되는지 `git check-ignore`로 확인.
- **4.10-5** Firebase 웹 설정값은 커밋하지 않는 로컬 설정 파일(또는 환경 변수)에서 빌드 때 넣는다(방식은 AI 재량, 2장 결정). 설정이 없으면 빌드는 자리표시 값으로 성공하고, 그 빌드의 확장 프로그램 화면은 로그인 대신 "Firebase 설정이 없습니다"류 안내를 보인다. AI는 이 PC에 설정 파일을 `apps:sdkconfig`로 만들어 둔다(커밋하지 않는다). 키 모양의 값을 나누거나 인코딩해 커밋 훅을 피하지 않는다.
  - 확인: 설정 없이 `npm run build`와 `check:build` 통과(CI가 이 경우다). 단위(설정이 없을 때 "설정 없음" 안내가 보이는지). 이 PC의 빌드에 실제 설정에서만 오는 값(`appId`)이 들어 있고 자리표시 빌드에는 없는지 빌드 결과 검색. 검색은 `grep -l`/`-c`로 파일 이름이나 개수만 보고, 값이 든 줄을 출력하거나 진행 기록에 붙이지 않는다.

### 4.11 검증 기반과 CI

- **4.11-1** 보안 규칙·저장소 통합 테스트는 에뮬레이터(`demo-` 프로젝트 id)로 돌고 운영 프로젝트에 닿지 않는다. 한 명령으로 돌린다(예: `npm run test:emulator`).

- 작업 브랜치: `firebase-sync`. main에 직접 커밋하지 않는다.
- 머지: 사용자가 `review-done`에서 통과와 머지를 승인하면 `firebase-sync`를 main에 머지하고(fast-forward가 되면 fast-forward, 아니면 머지 커밋) origin/main에 push한다. 머지 뒤 main의 CI가 성공하는지 본다.
- 운영 프로젝트에는 보안 규칙·색인·Hosting 배포와 6장·4.8-5의 설정만 한다. 배포는 작업 브랜치에서 CLI 명령으로만 하고, GitHub 연동 자동 배포는 켜지 않는다. 배포 뒤 점검이 실패하면 고쳐서 다시 배포한다. 머지 전에 규칙을 고쳤으면 다시 배포해 운영 규칙이 main과 같게 둔다. AI는 운영 프로젝트에 로그인해 데이터를 만들거나 지우지 않는다(Google 로그인은 AI가 할 수 없다). 데이터가 필요한 확인은 에뮬레이터로 한다.

### 사전 승인

- `firebase-sync` 브랜치를 origin에 push한다. 횟수 제한 없음.
- npm 패키지 설치: 런타임 `firebase`, 개발용 `firebase-tools`, `@firebase/rules-unit-testing`과 테스트에 필요한 개발용 패키지.
- Firebase 에뮬레이터가 처음 돌 때 실행 파일을 내려받는 것(`~/.cache/firebase`). CI에서도 같다. E2E용 Playwright 브라우저 내려받기(로컬).
- 운영 프로젝트에 Firestore 보안 규칙과 색인을 Firebase CLI로 배포한다. 횟수 제한 없음.
- 운영 프로젝트의 Firebase Hosting에 개인정보처리방침·저작권 안내 페이지를 Firebase CLI로 배포한다. 횟수 제한 없음. 이 페이지는 공개된다.
- Google Cloud 콘솔에서 OAuth 동의 화면의 홈페이지·개인정보처리방침 주소와 승인된 도메인을 넣는다(게시 상태는 이미 "프로덕션"이다).
- CI 워크플로(`.github/workflows/ci.yml`)에 에뮬레이터 테스트를 더한다.
- 비용이 드는 일: 없음.

### 멈추고 물을 것

- Blaze 요금제, 결제 수단 등록, Cloud Functions 등 비용이 생길 수 있는 일이 필요할 때.
- `storage`, `unlimitedStorage`, `identity` 말고 다른 권한이나 `host_permissions`가 꼭 필요할 때.
- 사용자 데이터를 Firebase·Google 인증 말고 다른 곳으로 보내야 할 때.
- OAuth 동의 화면이 기본 권한(openid, email) 밖의 권한을 요구하거나, 검증 없이는 브랜딩 주소가 저장되지 않거나 로그인이 막힐 때(미검증 표시만 뜨면 멈추지 않는다, 2장 결정).
- 운영 프로젝트의 설정(지역, 요금제, 로그인 수단)을 6장과 다르게 바꿔야 할 때.
- 4.7 말고 다른 로컬 데이터를 지워야 할 때.
- main에 직접 push하거나 force push가 필요할 때.
- 커밋 훅이 막을 때. 값을 바꾸거나 나눠 훅을 피하지 않고, 그 부분을 보류하고 진행 기록에 적는다.
- 요구사항끼리 부딪쳐 둘 다 만족할 수 없을 때.

### AI 재량

- Firestore 데이터 구조(컬렉션·문서 나누기, 본문 조각 크기, 키 이름), 사용량 계산 방식, 규칙의 크기 상한 값.
- StorageArea를 Firestore로 구현하는 방식, 실시간 반영 방식(스냅샷 리스너 등), SDK 캐시 설정.
- 로그인을 어디서(서비스 워커, 확장 프로그램 화면) 처리할지와 화면 사이에 로그인 상태를 나누는 방식.
- 4.7-1의 지운 표시의 저장 위치·이름.
- 로그인·계정·탈퇴·사용량 화면의 위치와 모양(`docs/design.md` 안에서), 문구.
- 공개 페이지의 구성과 모양, Hosting 안의 경로.
- Firebase 웹 설정값을 빌드에 넣는 방식(설정 파일 위치·이름, 환경 변수), 설정이 없을 때의 자리표시 값. OAuth 클라이언트 id와 방침 주소를 빌드 설정으로 바꿀 수 있게 할지(기본값은 이 프로젝트의 값).
- E2E 도구의 위치(저장소 의존성 또는 `~/.cache/design-tools`)와 명령 이름.
- 화면 상태 설정(패널 표시·너비, 글자 크기 등)을 다른 기기의 열린 화면에 바로 적용할지 다음에 열 때 적용할지, 쓰기를 묶는 방식.
- `check:build`의 허용 도메인 목록과 검사 방식.
- 에뮬레이터 테스트 명령 이름과 구성.
