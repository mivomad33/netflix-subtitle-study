# 여러 기기 동기화(Firebase)

- 작성일: 2026-11-08
- 요약: Google 계정으로 로그인하고, 학습 기록(메모, 학습 완료, 읽던 위치, 설정, 넷플릭스 학습 기록)과 원서 본문을 Firestore 한곳에 저장해 여러 PC의 크롬에서 학습을 이어 하게 한다.
- 종류: 변경 건(로컬에만 저장하던 확장 프로그램의 저장소를 Firestore로 바꾼다)
- 단계: 나누지 않는다. 이 명세서 하나로 끝낸다(`docs/plan.md` 없음, 2장 결정).
- 이 문서는 기획과 요구사항만 담는다. 설계와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 저장소 `mivomad33/netflix-subtitle-study`는 GitHub **공개 저장소**다. 커밋하는 모든 것은 공개된다. Firebase 웹 설정값(apiKey, projectId 등)은 비밀 값이 아니고 확장 프로그램에 들어가므로 공개된다. 보호는 보안 규칙이 맡는다.

## 1. 목표

### 지금 상태

- 메모, 책·본문, 읽던 위치, 학습 완료, 설정은 모두 그 PC 크롬의 `chrome.storage.local`에만 있다. 다른 PC에서는 백업 파일을 내보내고 가져와야 이어 할 수 있다.
- 백업 가져오기는 키마다 `updatedAt`이 더 새 쪽을 남기며 합치고, 아무것도 지우지 않는다.

### 바꾸려는 이유

- 여러 곳에서 여러 기기로 학습을 이어 하고 싶다(사용자, 2026-11-08).
- 나중에 유료 기능을 붙일 수 있게 사용자 계정을 두고 싶다. 지금은 모두 무료다(사용자, 2026-11-08).

### 쓰는 사람

- Google 계정이 있는 누구나(2장 결정). 지금은 사용자 본인이 여러 PC에서 쓰고, 소스를 받아 직접 빌드한 사람도 같은 Firebase 프로젝트로 로그인한다. Chrome 웹 스토어에는 올리지 않는다(지금과 같다).
- 예상 규모: 사용자 수십 명 이하. 1GiB 무료 저장에 20MB 상한이면 약 50명이다. 사용자가 늘어 하루 한도에 자주 걸리면 Blaze를 다시 본다(2장 결정).

### 어느 수준이면 충분한가

- 한 PC에서 바꾼 것은 다른 PC에서 그 화면을 새로 열면 보인다. 이미 열려 있는 화면에도 10초 안에 반영된다(지금 두 탭 사이에 반영되는 것과 같은 모양).
- 지금 있는 기능은 로그인한 뒤 모두 지금처럼 동작한다.

## 2. 확정된 결정과 제약

### 이 명세서 전에 정한 것

- **Firebase를 쓴다**(사용자 결정, 2026-11-08). 이유: 사용자 계정을 두어 나중에 유료 기능(결제 상태를 계정에 붙이고 보안 규칙으로 강제)을 붙이기 쉽다. 뺀 안:
  - Google Drive 앱 전용 폴더: 서버 없이 0원이지만, 결제한 사용자만 쓰게 강제할 수 없다.
  - `chrome.storage.sync`: 전체 약 100KB, 키 512개 한도라 메모가 조금만 쌓여도 넘친다.
  - Supabase 무료 요금제: 1주일 쓰지 않으면 프로젝트가 일시정지된다.
- **지금은 모든 기능 무료**다. 유료 기능은 나중에 따로 정한다(사용자 결정, 2026-11-08).
- **원서 본문도 동기화한다.** 그 사용자 본인만 읽고 쓸 수 있고, 공유 기능은 만들지 않는다(사용자 결정, 2026-11-08). 이유: 새 기기에서 로그인만 하면 책과 학습을 이어 가게 하려고. 사용자가 넣은 글을 본인만 보게 보관하는 서비스는 흔한 모델이고, 공유가 없으면 저작권 위험이 낮다.
- **보안 규칙은 테스트로 확인하고, 탈퇴하면 그 사용자의 데이터를 모두 지우고, 저작권 신고 창구와 개인정보처리방침을 둔다**(사용자 결정, 2026-11-08).
- **운영 비용은 없거나 적게** 한다(사용자 결정, 2026-11-08).
- 앞 명세서의 "본문과 메모를 외부로 보내지 않는다"에, 사용자가 로그인했을 때 그 사용자의 Firebase 저장소로 보내는 예외를 둔다(사용자 결정, 2026-11-08).
- 읽기 음성은 기기 음성만 쓴다(2026-11-08 사용자 결정으로 온라인 음성을 뺐다). 이 명세서는 음성을 바꾸지 않는다.

### 이 명세서에서 정한 것

- **본문도 Firestore에 저장하고, Firebase는 무료 Spark 요금제로 둔다**(추천안·사용자 승인, 2026-11-08). 본문은 문서 한도(1MiB)에 맞게 나눠 저장한다.
  - 이유: Cloud Storage for Firebase는 2024년 9월 발표 이후 Blaze(사용량 과금, 결제 계정 연결)에서만 쓸 수 있다. Spark는 결제 수단이 없어 요금이 나올 수 없고, 한도를 넘으면 그날 요청만 막힌다.
  - 바뀐 결정: 처음 대화에서는 본문을 Cloud Storage에 두기로 했다(2026-11-08). 위 요금제 제약을 확인한 뒤 바꿨다.
  - 감수하는 것: Spark 한도는 모든 사용자 합계로 저장 1GiB, 하루 읽기 5만·쓰기 2만·삭제 2만이다(<https://firebase.google.com/docs/firestore/quotas>, 2026-11-08 확인).
  - 뺀 안: Cloud Storage + Blaze. 카드 등록이 필요하고 요금 상한이 없다. 유료 기능을 붙일 때 다시 본다.
  - 큰 결정 검토: 서로 다른 모델 셋이 각자 안을 냈고, 셋 다 Firestore + Spark를 냈다. 이 검토로 추천이 Cloud Storage에서 Firestore로 바뀌었다.
- **로그인은 Google 계정으로 한다**(추천안·사용자 승인, 2026-11-08). 크롬의 Google 계정 토큰으로 Firebase에 로그인하고, 그 밖의 로그인 수단은 두지 않는다.
  - 이유: 비밀번호를 따로 관리하지 않고 버튼 한 번으로 로그인한다.
  - 감수하는 것: 확장 프로그램 권한 `identity`와 `manifest.json`의 `oauth2` 항목을 새로 더한다. Google Cloud에 크롬 확장 프로그램용 OAuth 클라이언트를 등록한다.
  - 뺀 안:
    - 이메일·비밀번호: 새 권한은 없지만, 비밀번호 관리와 가입·재설정 화면, 메일이 필요하다.
    - `signInWithPopup` + offscreen 문서: 공개 호스팅 페이지와 `offscreen` 권한, CSP 변경이 필요해 더 무겁다.
  - 큰 결정 검토: 셋 중 둘이 Google 로그인(`chrome.identity`), 하나가 이메일·비밀번호를 냈다.
- **Google 로그인은 로그인 창 방식(`chrome.identity.launchWebAuthFlow`)으로 한다**(추천안·사용자 승인, 2026-11-08. 위 결정의 "크롬의 Google 계정 토큰"을 바꿨다). Google 로그인 창에서 받은 ID 토큰으로 Firebase에 로그인한다.
  - 이유: 크롬 토큰 방식(`getAuthToken`)은 크롬 프로필 자체에 로그인해야 한다(<https://developer.chrome.com/docs/extensions/reference/api/identity>, 2026-11-08 확인). 크롬에 로그인하지 않은 PC에서도 쓰게 한다.
  - 바뀌는 것: 권한은 `identity` 하나만 더하고, `manifest.json`의 `oauth2` 항목은 두지 않는다. OAuth 클라이언트는 웹 애플리케이션 유형이고, 리디렉션 주소 `https://flhkacfjjpipfoicbnmednajnhebihmb.chromiumapp.org/`를 등록한다(6장).
  - 뺀 안: 크롬 토큰 방식(처음 승인한 안).
- **20MB 상한은 앱이 합계로 막고, 보안 규칙은 문서 하나와 글 하나의 크기를 막는다**(추천안·사용자 승인, 2026-11-08).
  - 이유: 보안 규칙은 컬렉션을 모아 셀 수 없어 사용자별 합계를 강제할 수 없다(<https://firebase.google.com/docs/firestore/security/rules-conditions>, 2026-11-08 확인). Cloud Functions는 Blaze가 필요하다.
  - 감수하는 것: 앱을 거치지 않고 API를 직접 부르는 사용자는 합계를 넘길 수 있다.
  - 뺀 안: 쓸 때마다 사용량 문서를 함께 고치고 규칙이 검사하기. 구현이 복잡하고 쓰기마다 읽기·쓰기가 늘어 무료 한도를 더 쓴다.
- **백업 내보내기·가져오기는 둘 다 유지한다**(추천안·사용자 승인, 2026-11-08). 내보내기는 Firestore에 있는 그 사용자의 데이터를 파일로 받고, 가져오기는 파일을 Firestore에 합친다(지금처럼 키마다 `updatedAt`이 새 쪽을 남기고 아무것도 지우지 않는다). 지금 버전에서 받은 백업 파일도 가져올 수 있다. 가져온 데이터도 20MB 상한에 든다. 이유: 옛 데이터를 지우기 전에 받은 백업을 되살릴 길이 되고, 개인정보 내보내기 요청에도 답할 수 있다. 뺀 안: 내보내기만, 둘 다 빼기.
- 열린 질문("걱정되는 것, 하면 안 되는 것, 이미 아는 함정")에 사용자는 "특별히 없음"이라고 답했다(2026-11-08).
- **데이터의 원본은 Firestore 하나다. 기기마다 사본을 두고 동기화하지 않는다**(사용자 결정, 2026-11-08).
  - 로그인해야 앱을 쓴다. 메모, 책·본문, 읽던 위치, 학습 완료, 설정, 넷플릭스 학습 기록을 모두 Firestore에서 읽고 Firestore에 쓴다.
  - 화면 속도를 위해 Firebase SDK의 자체 캐시(IndexedDB)는 쓴다. 이 캐시는 SDK가 관리하는 임시 사본이고, 직접 만든 동기화·합치기 코드는 두지 않는다.
  - 이유: 데이터가 한곳에만 있으면 동기화 버튼, 합치기 규칙, 삭제 표시, 첫 로그인 합치기, 로그아웃 처리 같은 문제가 거의 사라진다. 넷플릭스는 온라인에서만 보므로 오프라인은 고려하지 않는다.
  - 바뀐 결정: 처음에는 기기에 사본을 두고 자동으로 동기화하기로 했다(추천안·사용자 승인, 2026-11-08). 사용자가 원격 저장을 제안해 바꿨다.
  - 감수하는 것: 읽기도 무료 한도에 들어가고, 한도를 넘으면 그날은 앱이 열리지 않는다.
- **가입은 누구나 할 수 있다**(사용자 결정, 2026-11-08). Google 계정이 있으면 가입해 쓸 수 있다.
  - 감수하는 것: 무료 한도는 모든 사용자가 함께 쓴다. 다른 사용자가 많이 쓰면 그날 모두가 멈출 수 있다.
  - 뺀 안: 허용한 계정만(추천했던 안). 사용자가 누구나 쓰는 쪽을 골랐다.
- **사용자마다 저장 상한을 20MB로 둔다**(추천안·사용자 승인, 2026-11-08). 본문을 포함한 그 사용자의 데이터 합계다. 이유: 한 사람이 공유 무료 한도(1GiB)를 다 쓰지 못하게 한다. 1GiB에 약 50명이 들어간다. 뺀 안: 50MB(약 20명), 상한 없음.
- **기존 데이터는 옮기지 않고 처음부터 시작한다**(사용자 결정, 2026-11-08). 이 PC의 `chrome.storage.local`과 넷플릭스 사이트 `localStorage`에 있는 학습 기록을 Firestore로 올리지 않는다. 로그인한 뒤의 앱은 빈 상태에서 시작한다.
  - 뺀 안: 처음 로그인할 때 지금 PC의 데이터를 Firestore로 한 번 올리고 원래 데이터는 남겨 두기(추천했던 안). 사용자가 처음부터 시작하는 쪽을 골랐다.
- **두 단계로 나눈다**(추천안·사용자 승인, 2026-11-08). 1단계는 넷플릭스 사이트 `localStorage`의 학습 기록을 확장 프로그램 공통 저장소로 옮기고, 2단계는 공통 저장소를 Firestore로 바꾸는 안이었다.
  - 이 결정은 원격 저장과 "처음부터 시작" 결정으로 근거가 사라졌다. 옮길 데이터가 없고, 넷플릭스 기록도 처음부터 Firestore에 쓰면 되기 때문이다.
- **명세서 하나로 한다**(추천안·사용자 승인, 2026-11-08. 위 두 단계 결정을 바꿨다). 로그인, 본문을 포함한 모든 데이터의 Firestore 저장, 넷플릭스 기록, 탈퇴, 개인정보·저작권 안내를 이 명세서에서 한다.
  - 이유: 원격 저장이라 본문만 기기에 남기는 중간 단계를 만들 수 없다. 저장소를 한곳(StorageArea)으로 모아 둔 기존 구조라 바꿀 곳이 모여 있다.

- **넷플릭스 자막 처리에 쓰는 값(`NF_lingoActive`, `NF_preferredTextLocale`)은 넷플릭스 `localStorage`에 그대로 둔다**(AI 판단, 2026-11-08). 학습 기록이 아니라 그 브라우저의 자막 처리 상태라서다. 나머지 이 확장 프로그램의 `NF_` 키(설정, 체크리스트, 공부한 영상 목록, 페이지당 대사 수, 예전 메모)는 앞으로 Firestore에 쓰고, 로컬에 남은 옛 값은 옮기지 않고 지운다.
- 사용 통계는 모으지 않는다. Firebase Analytics 등 분석 도구를 붙이지 않는다(AI 판단, 2026-11-08. 개인정보처리방침을 작게 유지한다).
- **Firebase는 무료 Spark 요금제를 유지한다**(추천안·사용자 승인, 2026-11-08). 하루 한도에 걸리면 그날은 앱이 멈추고, 무료 사용량을 다 썼다고 안내한다. 사용자가 늘면 그때 Blaze를 다시 본다. 뺀 안: Blaze + 예산 알림(카드 등록이 필요하고, 예산 알림은 과금을 막지 못한다).

### 제약

- 크롬 확장 프로그램 Manifest V3다. 확장 프로그램 ID는 `manifest.json`의 `key`로 고정돼 있다(`flhkacfjjpipfoicbnmednajnhebihmb`).
- 확장 프로그램은 PC 크롬에서만 돈다. 휴대폰·태블릿은 이번 대상이 아니다.
- 넷플릭스 페이지의 코드는 `chrome.*`를 쓸 수 없고, content script와 검증된 메시지로만 저장소를 쓴다(앞 명세서의 브리지). 넷플릭스 쪽에 계정 정보나 다른 데이터가 새로 노출되면 안 된다.

## 4. 요구사항

용어

- **사용자**: Google 계정으로 로그인한 사람. Firebase 사용자 id(uid)로 구별한다.
- **운영자**: Firebase 프로젝트 소유자(`hunt24333@gmail.com`). 관리자 화면은 없고 Firebase 콘솔을 쓴다.

### 4.1 로그인

- **4.1-1** 확장 프로그램 화면에 "Google로 로그인" 버튼이 있고, 누르면 Google 로그인 창(`launchWebAuthFlow`)이 열린다. 계정을 고르면 Firebase에 로그인되고, 화면에 로그인한 계정의 이메일이 보인다.
  - 확인: 단위(가짜 로그인 창·가짜 Firebase Auth로 버튼 → 로그인 → 이메일 표시). 실제 Google 로그인은 AI가 할 수 없어 "사용자가 마지막에 확인한다".
- **4.1-2** 로그인하지 않았으면 원서 리더·메모 모아 보기·넷플릭스 학습 패널이 데이터를 읽지도 보여 주지도 않고, 로그인 안내를 보인다. 넷플릭스 화면의 안내는 확장 프로그램 화면을 여는 링크를 준다(넷플릭스 화면에서 직접 로그인하지 않는다).
  - 확인: 단위(로그아웃 상태에서 각 화면이 저장소를 부르지 않고 안내를 보이는지, 로그인 상태에서는 데이터가 보이는지).
- **4.1-3** 로그인은 브라우저를 껐다 켜도 유지되고, 로그아웃할 때까지 남는다. 로그인 만료나 취소된 계정이면 로그인 안내로 돌아간다.
  - 확인: 단위(인증 상태 변화에 따라 화면이 바뀌는지). 브라우저 재시작 유지는 "사용자가 마지막에 확인한다".
- **4.1-4** 로그아웃하면 Firebase에서 로그아웃하고, Firestore SDK 캐시(IndexedDB)를 지운다(`terminate` 뒤 `clearIndexedDbPersistence`). 같은 PC에서 다른 계정으로 로그인하면 앞 계정의 데이터가 한 글자도 보이지 않는다.
  - 확인: 통합(계정 A로 쓰고 로그아웃 → 캐시가 비었는지, 계정 B로 로그인 → A의 데이터가 없는지).
- **4.1-5** 로그인 창을 닫거나 취소하면 오류 없이 로그인 전 화면으로 돌아가고 "로그인을 취소했습니다"류 안내를 보인다.
  - 확인: 단위(가짜 로그인 창이 취소를 돌려줄 때).

### 4.2 저장

- **4.2-1** 메모(넷플릭스·원서), 책 정보와 본문, 읽던 위치, 학습 완료, 원서 리더 설정, 넷플릭스 학습 기록(영상별 체크리스트·회차, 공부한 영상 목록, 페이지당 대사 수, 패널·재생·자막 설정)을 모두 그 사용자의 Firestore 영역에 읽고 쓴다. 로컬(`chrome.storage.local`, 넷플릭스 `localStorage`)에는 이 데이터를 쓰지 않는다(SDK 캐시와 2장의 자막 처리 값 둘은 예외).
  - 확인: 통합(각 종류를 쓰고 새 클라이언트로 읽으면 같은 값). 단위(저장 코드가 `chrome.storage.local.set`과 2장 예외 밖의 `localStorage.setItem`을 부르지 않는지 가짜 저장소로 확인).
- **4.2-2** 지금 있는 기능(메모 쓰기·고치기·지우기·검색, 책 가져오기·지우기, 장 읽기, 읽던 위치, 학습 완료·진행률, 소리 내어 읽기 설정, 넷플릭스 체크리스트·대시보드)은 로그인한 뒤 지금처럼 동작한다.
  - 확인: 기존 단위 테스트가 모두 통과한다(테스트용 메모리 저장소는 남겨도 된다). 통합(저장소를 Firestore 구현으로 바꿔 기존 저장소 테스트(`repo.test.ts` 등)와 같은 경우를 돌린다).
- **4.2-3** 한 곳(다른 PC나 다른 탭)에서 바꾼 것이 이미 열린 다른 화면에 10초 안에 반영된다. 새로 연 화면에는 바로 보인다.
  - 확인: 통합(두 클라이언트를 에뮬레이터에 붙여, 한쪽에서 쓰고 다른 쪽의 변경 알림이 10초 안에 오는지).
- **4.2-4** 큰 본문(장 하나가 문서 한도 1MiB를 넘는 경우 포함)도 저장하고 그대로 다시 읽는다.
  - 확인: 통합(1.5MiB 넘는 장을 쓰고 읽어 같은지, 책을 지우면 나눠 둔 조각도 모두 지워지는지).
- **4.2-5** 지금 있는 성능 기준(`scripts/perf/measure.mjs`의 여섯 시간)은 개발 화면에서 그대로 통과한다. 운영 프로젝트에서 장 열기는 SDK 캐시가 있을 때 1초 이하다.
  - 확인: `node scripts/perf/measure.mjs` 통과(개발 화면). 운영 프로젝트의 속도는 AI가 로그인할 수 없어 "사용자가 마지막에 확인한다".
- **4.2-6** 저장이 실패하면(권한 거부, 상한, 무료 한도 초과, 오래 연결되지 않음) 조용히 버리지 않고 4.4의 안내를 보인다. 연결이 잠깐 끊긴 동안의 쓰기는 SDK가 다시 보내도 된다.
  - 확인: 단위(가짜 저장소가 각 오류를 낼 때 안내가 보이는지).

### 4.3 넷플릭스 화면과 브리지

- **4.3-1** 넷플릭스 화면의 학습 기록과 설정은 지금처럼 content script를 거치는 브리지로 읽고 쓴다. 넷플릭스 화면은 넷플릭스 메모와 넷플릭스 학습 기록만 다룰 수 있고, 책·본문·원서 메모·계정 정보(이메일, uid, 토큰)는 받을 수 없다.
  - 확인: 단위(`handler.test.ts`에 더한다: 허용 작업은 통과, 책·원서 메모·계정 정보를 읽으려는 요청과 형식이 틀린 요청은 거부. 넷플릭스 메모와 닮은 원서 메모 id도 거부).
- **4.3-2** 넷플릭스 화면이 로그인 상태를 알아야 하면 "로그인됨/안 됨" 하나만 받는다.
  - 확인: 단위(브리지 응답에 그 밖의 계정 필드가 없는지).
- **4.3-3** 넷플릭스 화면의 브리지 요청 형식 검사(같은 창·같은 출처·아는 작업·길이 상한)를 새 작업에도 지금과 같은 수준으로 둔다. 체크리스트·영상 목록 같은 새 값에는 크기 상한을 둔다.
  - 확인: 단위(상한을 넘는 값과 형식이 틀린 값은 거부, 상한 바로 아래 값은 통과).

### 4.4 상한과 오류 안내

- **4.4-1** 앱은 그 사용자의 저장량 합계를 알고, 쓰기 뒤 합계가 20MB(20×1024×1024바이트, 크기 계산 방식은 AI 재량이되 Firestore 저장 크기보다 작게 세지 않는다)를 넘는 쓰기는 보내지 않고 "저장 공간 20MB를 다 썼습니다"류 안내를 보인다. 원서 리더의 설정이나 백업 근처에 "사용량 n MB / 20MB"를 보인다.
  - 확인: 단위(상한 바로 아래로 끝나는 쓰기는 통과, 넘는 쓰기는 거부, 지운 뒤에는 다시 쓸 수 있음).
- **4.4-2** Firestore가 무료 한도 초과(`resource-exhausted`)를 돌려주면 "오늘 무료 사용량을 다 썼습니다. 한도는 태평양 시간 자정(한국 시간 오후 4시 또는 5시)에 다시 채워집니다"류 안내를 보이고, 다시 시도 버튼을 둔다.
  - 확인: 단위(가짜 저장소가 그 오류를 낼 때. 다른 오류에서는 이 안내가 나오지 않음).
- **4.4-3** 네트워크 끊김, 권한 거부, 로그인 만료는 서로 다른 안내를 보인다. 안내에 개인정보(이메일 외)와 내부 오류 문자열을 그대로 보이지 않는다.
  - 확인: 단위(오류 종류별 문구).
- **4.4-4** 로그인 확인, 첫 읽기처럼 오래 걸릴 수 있는 동작에는 대기 표시를 보인다.
  - 확인: 단위(대기 중 표시가 보이는지), 화면은 4.9.

### 4.5 보안 규칙

- **4.5-1** Firestore 보안 규칙은 로그인한 사용자가 자기 uid 영역만 읽고 쓰게 한다. 로그인하지 않은 요청, 다른 uid 영역, 자기 uid로 시작하지만 다른 uid(예: `abc`와 `abcd`) 영역, 영역 밖 경로는 모두 거부한다. 기본은 거부다.
  - 확인: 통합(`@firebase/rules-unit-testing`과 에뮬레이터. 허용과 거부 경우를 모두 테스트). 일부러 규칙을 모두 허용으로 바꾸면 거부 테스트가 실패하는지 한 번 보고 진행 기록에 적는다.
- **4.5-2** 규칙은 문서 하나와 문자열 필드 하나의 크기에 상한을 둔다(값은 AI 재량. 앱이 쓰는 가장 큰 정상 문서는 통과해야 한다).
  - 확인: 통합(상한 바로 아래는 통과, 넘으면 거부).
- **4.5-3** 저장소의 규칙 파일이 운영 프로젝트에 배포된 규칙과 같다.
  - 확인: Firebase CLI로 배포한 뒤, 배포된 규칙을 읽어 저장소 파일과 비교한다(명령과 결과를 진행 기록에).

### 4.6 탈퇴

- 작업 브랜치: `firebase-sync`. main에 직접 커밋하지 않는다.
- 머지: 사용자가 `review-done`에서 통과와 머지를 승인하면 `firebase-sync`를 main에 머지하고(fast-forward가 되면 fast-forward, 아니면 머지 커밋) origin/main에 push한다. 머지 뒤 main의 CI가 성공하는지 본다.
- 운영 프로젝트에는 보안 규칙·색인 배포와 6장의 설정만 한다. AI는 운영 프로젝트에 로그인해 데이터를 만들거나 지우지 않는다(Google 로그인은 AI가 할 수 없다). 데이터가 필요한 확인은 에뮬레이터로 한다.

### 사전 승인

- `firebase-sync` 브랜치를 origin에 push한다. 횟수 제한 없음.
- npm 패키지 설치: 런타임 `firebase`, 개발용 `firebase-tools`, `@firebase/rules-unit-testing`과 테스트에 필요한 개발용 패키지.
- 운영 프로젝트에 Firestore 보안 규칙과 색인을 Firebase CLI로 배포한다. 횟수 제한 없음.
- 이 저장소의 GitHub Pages를 켜고(소스 방식은 AI 재량), 개인정보처리방침·저작권 안내 페이지를 배포한다. 이 페이지는 공개된다.
- Google Search Console에서 GitHub Pages 주소(`mivomad33.github.io` 아래)를 소유 확인한다(확인용 파일이나 메타 태그를 Pages에 올린다).
- Google Cloud 콘솔에서 OAuth 동의 화면의 홈페이지·개인정보처리방침 주소와 승인된 도메인을 넣고, 게시 상태를 "프로덕션"으로 바꾼다.
- CI 워크플로(`.github/workflows/ci.yml`)에 에뮬레이터 테스트를 더한다.
- 비용이 드는 일: 없음.

### 멈추고 물을 것

- Blaze 요금제, 결제 수단 등록, Cloud Functions 등 비용이 생길 수 있는 일이 필요할 때.
- `storage`, `unlimitedStorage`, `identity` 말고 다른 권한이나 `host_permissions`가 꼭 필요할 때.
- 사용자 데이터를 Firebase·Google 인증 말고 다른 곳으로 보내야 할 때.
- OAuth 동의 화면이 기본 권한(openid, email, profile) 밖의 권한이나 앱 검증·브랜드 검증을 요구할 때.
- 운영 프로젝트의 설정(지역, 요금제, 로그인 수단)을 6장과 다르게 바꿔야 할 때.
- 4.7 말고 다른 로컬 데이터를 지워야 할 때.
- main에 직접 push하거나 force push가 필요할 때.
- 요구사항끼리 부딪쳐 둘 다 만족할 수 없을 때.
